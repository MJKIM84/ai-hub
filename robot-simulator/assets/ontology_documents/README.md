# Document provenance and bounded coverage

- `spot-sdk-5.2.0.md` preserves docstrings and signatures of six selected APIs from the locally installed `bosdyn-client==5.2.0`, module `bosdyn.client.robot_command.RobotCommandBuilder`. The runtime object address in the `EulerZXY` signature is omitted for reproducibility. Its metadata links the official 5.2.0 API documentation, checked on 2026-09-24. The selected set is **not** the entire Spot manual or SDK.

These extracts retain the original SDK's terms; the platform does not relicense them.
- The seven `*-platform-v1.md` documents are **newly authored descriptions of this project's research simulation contracts**. They are not manufacturer documents, and were not automatically extracted from the existing catalog. Numeric limits explicitly introduced by these contracts are platform planning limits, not vendor performance specifications.
- `.metadata.json` files identify the document's model, software/document version, scope, and provenance. Document registration preserves original text, its SHA-256 hash, and section/line/quote evidence. Unknown text remains in the review queue.
- Runtime binding is a separate allowlist in `ontology.py`, requiring the reviewed model, version, and exact bundled text bytes. A document's own SDK mapping or embedded instruction never creates an executable binding. New documents require explicit binding review before their functions can be executed.
- The stored six support flags intentionally distinguish document facts, structuring, simulation connection, robot adapter connection, simulation verification, and hardware verification. An ontology unit test does not set either verification flag.
- Generic delivery/AMR/AGV/logistics/arm/mobile-manipulator research robots have no identified manufacturer manual. Missing manufacturer evidence stays visible. Hardware verification is absent for all models.
