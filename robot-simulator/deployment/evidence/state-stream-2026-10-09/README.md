# 라이브 움직임 끊김 수정 — 2026-10-09 KST

## 확인한 원인과 수정

운영 서버와 브라우저 사이의 순차 GET 요청에서 새 상태가 약 0.8초 간격으로 도착했다. 기존 `SceneMotion`은 간격이 250ms를 넘으면 보간을 끄고, 나머지도 최대 120ms까지만 보간했다. 물리 실행은 진행되지만 화면은 수신 때만 위치가 바뀌는 상태였다.

- `/api/state/stream`으로 실제 스냅샷을 최대 20Hz 전달한다. 매 프레임 네트워크 왕복을 기다리지 않는다. 변경된 최상위 필드만 전송하며 연결/실행이 바뀌면 전체 기준 상태를 보낸다.
- 연결은 90초마다 재연결하며, 실행 공간 종료 시 정리된다. 방문자 격리·비밀번호 보호·출처 검사 유지, 실행 공간당 스트림 2개 제한. 명령 전송이나 모델 호출은 없다.
- 수신 순서 번호로 늦은 GET/스트림 응답이 일시정지·초기화한 상태를 되돌리지 않게 한다. 스트림이 불가능하면 기존 GET으로 전환한다.
- 수신 간격에 맞춰 화면 보간 시간을 조절한다. 로봇·사람·물품은 받은 물리 위치 사이만 표시하며 미래 위치를 추측하지 않는다. 사람의 보행 자세와 따라가기 카메라도 표시 중인 위치를 사용한다.
- 일시정지·연결 단절·실행 변경·물리 진단에서는 실제 수신 위치로 맞춘다. 물리 속도, 안전거리, 계획, 작업 완료 기준은 변경하지 않았다.

## 실제 브라우저 측정

같은 Mac의 내장 브라우저에서 운영 실행 공간의 `canvas[data-rendered-frames]`와 `data-motion`을 읽었다. 수정 후에는 `data-packet-gap-ms`도 기록했다. 측정 도중에는 카메라를 조작하지 않았다. 수정 전후 모두 기본 다층 물품 예제를 1배속으로 사용했으나 서로 다른 실행 구간이므로 물리 처리량 비교로 해석하지 않는다.
