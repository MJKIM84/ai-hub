## 배포 과정에서 수정하고 다시 확인한 내용

- Sandbox 목록 조회 한도를 실제 API가 허용하는 50 이하로 수정했다.
- Ubuntu 실행 이미지의 실제 소스 위치를 확인하고 실행 소스를 `/opt/robot-app/robot-simulator`로 복사했다.
- 3D 형상 JSON 약 27.4MB가 화면의 5초 요청 제한에 걸려 비어 있던 문제를 수정했다. 공개 응답에 gzip을 적용하고 장면 요청만 60초 제한으로 분리했다. 상태 조회의 5초 제한은 유지했다.
- 수정 커밋 `42f31317d027e1f65b6b17790a5e18378f374e06`으로 새 이미지 `snap_fXEC3VELYq3Ga7cAyYXrDgUvrmk4`를 만들고 운영에 반영했다. 위 전체 실행 이후의 변경은 배포 경로·목록 조회·압축·화면 요청 시간이며 물리/관제 로직을 변경하지 않았다.
- 수정된 이미지의 새 Chrome 체험에서 로봇 5대, 사람, 3D 형상, 물품 상차, 보행자 양보 대기, 로봇 선택·따라가기, 출발층/도착층 동시 표시, 2층 선택, 시작·일시 정지를 확인했다. 이 두 번째 UI 확인은 38초대까지이며 전체 시나리오의 두 번째 완주라고 주장하지 않는다.
- 로컬 방문자 격리·공개 실행 검사 30개와 Node 세션 수명·상한 검사 12개 통과. 웹 빌드 통과. GitHub CI의 Linux 검사와 컨테이너 물리 시작 검사도 통과했다.

## 운영 범위

체험은 최대 30분이며 사용자가 탭을 닫아도 종료 시간까지 유지된다. 시작 페이지의 종료 버튼으로 일찍 종료할 수 있다. 기본 동시 입장 검사 2개, UTC 일일 생성 상한 10개이며, 동시 입장 검사는 경쟁 요청에 대한 엄격한 동시성 상한이 아니다. 종료한 이름도 같은 날 재사용하지 않는다. 전체 결제액 상한과 같지 않다.

준비된 예제에는 모델 키가 필요 없다. 실제 AI 대화는 방문자 본인 API 연결과 동의가 필요하다. 이번 배포 검증에서는 실제 유료 모델 호출·실물 로봇 제어·새 안전성 인증을 수행하지 않았다. Linux에서 macOS 전용 OCR을 제공하지 않는 제한도 유지한다.
