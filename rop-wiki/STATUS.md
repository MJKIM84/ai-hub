# ROP 연구 위키 현황 점검

- 기준일: 2026-09-25
- 브랜치: `claude/stoic-maxwell-4spa1k`
- 관련 문서: [구축 완료 보고서](BUILD_REPORT.md), [구축 [가정] 전체 목록](BUILD_ASSUMPTIONS.md)

## 요약

위키 구조, 에이전트, 파이프라인은 모두 동작하고 드라이런 두 번이 게시까지 통과했다. 실제 운영은 아직 시작 전이다. 28개 세부영역 가운데 본문이 있는 곳은 1개뿐이고, 상시 스케줄이 없으며, 출처 원문을 한 건도 열어 보지 못했다.

## 2. 미구현 부분

- **알림:** 설정의 `notify` 값에 따른 슬랙·이메일 발송은 자리만 있고 발송 코드는 없다.
- **정정 요청 거절 처리:** 반영하지 않기로 한 정정 요청을 자동으로 `rejected` 로 바꾸는 기능이 없다. 지금은 사람이 `inbox/corrections.md` 의 상태를 직접 바꾼다.
- **사이트 배포:** 로컬 빌드만 된다. 원격 푸시(`git_push`)도 꺼져 있다.
- **상시 스케줄:** 등록 스크립트(`pipeline/install_cron.sh`)가 동작하는 것만 확인했다. 운영 서버에는 등록되어 있지 않다.

## 3. 미검증 부분

코드는 있지만 실제 에이전트로 돌려 보지 않은 것이다.

- **실행 유형 4가지:** 주제 조사, 갱신, 주간 정리, 월간 재검증. 가짜 응답을 쓴 종단 테스트만 거쳤다.
- **대상 선정 규칙:** 2주기 점수식 선정, 연속 3회 보류 영역 제외, 트랙 단계 전환.
- **사용자 입력 반영:** 정정 요청(`inbox/corrections.md`)과 실험 결과(`experiments/`)를 받아 반영하는 흐름.
- **원문 열람 정상 모드:** 두 드라이런 모두 원문을 열 수 없는 모드(`--allow-no-fetch`)로 돌았다.
- **참고문헌 URL:** 실제로 열리는지 확인하지 못했다(완료 기준 3).

## 4. 문제 부분

1. **원문 미열람:** 품질을 가장 크게 제한하는 요인이다. 네트워크 정책으로 외부 페이지 열람이 막혀 모든 출처의 신뢰도가 medium 이하이고, 드라이런 1의 교차 확인은 0건이다. 모델·표준 비교표도 대부분 "미확인"이다.
2. **퍼블리셔 실패:** 드라이런마다 한 번씩 실패했다. 버그 5개는 고쳤지만, 에이전트가 만든 형식 오류를 퍼블리셔가 사후에 잡는 구조라 새로운 형식 오류가 또 나올 수 있다.
3. **분량 초과:** 스토리텔러가 처음 쓴 글이 분량 기준(세부영역 4,000자)을 넘기곤 한다. 드라이런 1은 두 번 다시 써야 했고, 소요 시간의 절반 가까이가 재작성이었다.
4. **상태 표기 불일치:** 온톨로지 초안 본문에는 "페이지 상태: draft" 로 적혀 있지만 실제 상태는 `published` 다. 본문에 적은 상태 줄은 퍼블리셔가 갱신하지 않는다.
5. **비용:** 아래 표와 같이 크다.
6. **형식 불일치:** 시드 참고문헌 10건은 3개 절이고, 퍼블리셔가 새로 만드는 항목은 5개 절이다. 용어집 시드 13개는 검증을 거치지 않은 `draft` 상태 그대로다.
7. **브랜치 이력:** 커밋 39개 중 17개가 작업 중간 스냅샷이다. PR을 만들기 전에 정리하는 편이 좋다.
8. **사양 충돌:** 트랙 시작 질문의 "(13번)" 같은 표현은 사양서 10장의 "번호만으로 부르지 않기" 규칙과 부딪힌다. 지금은 원문을 그대로 두고 표 아래에 번호와 이름을 보충해 두었다.

| 비용·시간 | 값 |
|---|---|
| 1회 실행 | 약 $14~16, 약 30분 |
| 매일 실행 시 월 추정 | 약 $420~480 |
| 에이전트 프롬프트 1회 크기 | 약 7만~21만 자 |

## 5. 개선 필요 부분

우선순위순이다.

1. **원문 열람 환경:** 원문을 열 수 있는 환경에서 운영하고, `ROP_CHECK_URLS=1 bash pipeline/checks/run_all.sh` 후 `python3 pipeline/scaffold.py --apply-url-check` 로 참고문헌 신뢰도를 올린다.
2. **스케줄 등록:** 항상 켜진 곳에 등록한다. 어디에 둘지 결정이 필요하다(보고서 3절 2번).
3. **사전 검사:** 스토리텔러 출력 직후 분량, 태그 형식, 링크 대상을 스크립트로 먼저 검사해 2차 검증 전에 되돌려 준다. 재작성 횟수와 비용이 준다.
4. **프롬프트 축소:** 입력 파일 전문 대신 요약을 넣고, 검증 에이전트에는 더 저렴한 모델을 검토한다.
5. **미검증 유형 검증:** 주제 조사, 갱신, 주간 정리, 월간 재검증을 드라이런으로 한 번씩 돌린다.
6. **상태 줄 동기화:** 퍼블리셔가 본문의 상태 줄을 프런트매터와 자동으로 맞추게 하거나, 스토리텔러가 본문에 상태를 쓰지 않게 한다.
7. **미구현 기능:** 알림 발송과 정정 요청 거절 처리를 구현한다.
8. **형식 정리:** 참고문헌 시드 10건을 퍼블리셔 형식으로 맞추고, 용어집 시드 13개를 검증 실행에 태운다.
9. **이력 정리:** PR 전에 중간 스냅샷 커밋을 정리한다.
