## 3. 사용자 결정이 필요한 항목

각 항목에 기본값을 적었다. 답이 없으면 기본값으로 운영된다.

1. **운영 환경에서 외부 페이지 열람을 허용할 수 있습니까?** 기본값: 허용된 환경에서 운영한다(`web_fetch_required: true`, 사양서대로 열람 불가 시 중단). 이 세션 같은 환경에서 계속 돌리려면 실행마다 `--allow-no-fetch` 를 준다. 이 세션의 클라우드 환경에서 열람을 허용하려면 환경 설정의 Network access 에서 접근 수준을 넓히거나 참고 도메인(ref.gs1.org, arxiv.org, nist.gov, design.ros2.org 등)을 허용 목록에 넣는다.
2. **일일 실행을 어디에 등록합니까?** 기본값: 항상 켜진 리눅스 서버에서 `bash pipeline/install_cron.sh`(매일 06:00 Asia/Seoul). 대안은 Claude Code 예약 작업(루틴)이나 GitHub Actions 다. 이 컨테이너의 crontab 에는 등록돼 있지만 cron 데몬이 돌지 않고 컨테이너가 사라지므로 운영용이 아니다.
3. **cron 환경의 Claude 인증 방식은 무엇으로 합니까?** 기본값: `claude setup-token` 장기 토큰. 대안: `ANTHROPIC_API_KEY`.
4. **실행당 커밋을 두 개(실행 + 해시 기록)로 둡니까?** 기본값: 두 개. 하나만 원하면 `summary.json` 의 `commit` 을 비워 둔다.
5. **실행 커밋을 원격에 자동 푸시합니까?** 기본값: 푸시하지 않는다(`git_push: false`). 사이트 배포(예: GitHub Pages)는 이번 범위 밖이다.
6. **트랙 실행 요일은 화·금으로 둡니까?** 기본값: 화·금(주 2회).
7. **트랙 실행일과 주간 정리·월간 재검증이 겹치면 어느 쪽이 먼저입니까?** 기본값: 트랙이 먼저이고 정기 실행은 다음 실행으로 미룬다.
8. **정정 요청이 트랙·주간 정리 날에 들어오면 그날 반영합니까?** 기본값: 다음 영역 실행으로 미룬다.
9. **대분류 페이지의 7번째 절 "참고 자료"와 표 전체 자동 갱신을 유지합니까?** 기본값: 유지한다.
10. **참고문헌 페이지 구조를 통일합니까?** 시드 10건은 3개 절, 퍼블리셔가 만드는 새 항목은 5개 절(서지 정보·비고 포함)이다. 기본값: 시드 10건을 퍼블리셔 형식으로 맞춘다.
11. **표준·프레임워크 목록에 '프레임워크' 종류를 두고 ROS 2 DDS-Security 를 그 종류로 둡니까?** 기본값: 유지한다.
12. **트랙 시작 질문 원문에 있는 번호만의 호칭("(13번)" 등)을 그대로 둡니까?** 사양서 10장은 번호만 호칭을 금지하지만 8.1 은 질문을 원문 그대로 백로그 시드로 쓰라고 한다. 기본값: 원문을 두고 표 아래에 번호와 이름을 보충한다.
13. **에이전트 모델과 비용 수준을 유지합니까?** 기본값: `claude-opus-5-5`. 드라이런 기준 1회 약 $14~16, 약 30분이다.
14. **정정 요청을 반영하지 않기로 한 경우(`rejected`)의 자동 처리를 추가합니까?** 기본값: 지금은 사람이 상태 줄을 바꾼다.

## 4. 알려진 한계와 다음 개선 후보

**한계**

- 출처 원문을 한 건도 열지 못했다. 드라이런 1의 교차 확인은 0건이고, 모델·표준 비교표의 정보 항목 열은 대부분 "미확인"이다.
- 완료 기준 3(참고문헌 URL 열림)과 7(상시 스케줄)은 이 환경에서 끝낼 수 없었다.
- 스토리텔러가 첫 작성에서 분량 기준(세부영역 4,000자)을 넘기는 경향이 있다. 드라이런 1은 재작성 2회가 필요했고 소요 시간의 절반 가까이가 재작성이었다.
- 두 드라이런 모두 퍼블리셔에서 한 번씩 실패했다. 원인은 모두 고쳤지만, 에이전트 산출물의 새 형식 오류를 퍼블리셔가 사후에 잡는 구조다.
- 적대적 검토 뒤 남은 경미한 지적(표현·중복 설명 수준) 일부는 고치지 않았다.
- 트랙 단계 1은 아직 완료 조건을 채우지 못했다(q1-03~q1-08 남음).

**다음 개선 후보**

- 페이지 열람이 되는 환경에서 `ROP_CHECK_URLS=1 bash pipeline/checks/run_all.sh` 후 `python3 pipeline/scaffold.py --apply-url-check` 로 참고문헌 신뢰도를 올린다.
- 스토리텔러 출력 직후 스크립트가 분량·태그 형식을 측정해 2차 검증 전에 되돌려 주면 재작성 횟수와 비용이 준다.
- 퍼블리셔 2단계에 링크 대상 형식 검사(경로·URL 이 아닌 링크)를 추가해 빌드 전에 잡는다.
- `corrections_rejected` 처리를 스키마와 퍼블리셔에 추가한다.
- 1주기 진행에 맞춰 운영 지표에서 영역별 비용·재작성 횟수를 집계한다.

## 5. 실행 방법 요약

위키 루트(`rop-wiki/`)에서 실행한다.

```bash
pip install -r requirements.txt                      # 처음 한 번
bash pipeline/checks/run_all.sh                      # 전체 검사 + 엄격 빌드

bash pipeline/run_daily.sh                           # 오늘 정규 실행(대상 선정 규칙대로)
bash pipeline/run_daily.sh --run-type area_deep_dive --area 7          # 영역 지정
bash pipeline/run_daily.sh --run-type track --track manual-capability-ontology --stage 1
bash pipeline/run_daily.sh --allow-no-fetch          # 페이지 열람이 막힌 환경(원문 미열람 모드)
bash pipeline/run_daily.sh --resume <실행 id> --step publish           # 퍼블리셔만 다시

bash pipeline/install_cron.sh                        # 매일 06:00 Asia/Seoul 등록
crontab -l                                           # 확인
bash pipeline/uninstall_cron.sh                      # 해제

mkdocs serve                                         # 로컬 미리보기
```

- 결과 확인: `runs/<실행 id>/log.md`, `docs/logs/daily/<날짜>.md`, `docs/changelog.md`.
- 정정 요청: `inbox/corrections.md` 에 항목을 추가하면 다음 영역 실행의 검증 항목에 들어간다. 형식은 `docs/corrections.md` 에 있다.
- 우선 지정: `config/priority.yaml` 의 `areas`·`topics`·`questions`·`track_questions`.
- 보류 산출물: `runs/parked/<실행 id>/` 를 검토하고 `--resume <실행 id>` 로 재투입한다.
