# 21. 상호운용 표준·적합성 — 보완 조사

## 요약

- VDA 5050 3.0.0은 문서의 발행 월, 웹 게시 날짜, GitHub 릴리스 시각, 보도자료 날짜를 구분해야 한다. 정확한 단일 채택일은 이번 자료만으로 확정하지 않는다. [의견][^n1][^n2][^n3][^n4]
- 연동 승인은 버전 문자열 확인에 더해 선택 필드, 주문 재전송, 취소 후 갱신의 동작 시험을 포함하도록 제안한다. [의견][^n1]
- 릴리스 태그의 JSON 구문 오류를 직접 재현했다. 규격 PDF, 스키마, 검사 도구를 각각 고정하고 예외를 기록하는 절차를 제안한다. [의견][^n1][^n6]
- 국내에서는 2026년 TTA 표준 목록과 KS 부합화 표준을 추가 확인했다. ISO 21423은 공식 목록상 발행 준비 단계다. 아래 B10~B12에 확인 범위를 한정한다. [사실][^n11][^n15][^n16]
- 자체 검사, 공급자 간 인증 발표, 전시 시연, 독립 시험소 인증을 서로 다른 근거 수준으로 관리해야 한다. [의견][^n7][^n8][^n17][^n18][^n20]

조사 기준은 2026-10-11에 열람한 공개 자료다. 최근 1년은 2025-10-01~2026-10-11로 한정했다. 카탈로그를 읽은 것과 유료 표준 본문을 읽은 것을 구분한다. 이 파일은 보완 제안이며 위키에는 반영하지 않았다.

## 보완 항목

### [7. 관련 표준·프레임워크·오픈소스] — 수정

**B01. VDA 5050 발행일의 종류를 분리한다.**

- 대상 문장 발췌: “발행일은 명세 머리에 없어 미확인”. 위치: 분리된 7절 표의 VDA 5050 행.
- 새 내용: 공식 PDF 표지는 3.0.0을 2026년 3월 판으로 표시한다. [사실][^n1] 공식 게시 페이지에는 2026-03-17이 표시된다. [사실][^n2] GitHub 릴리스 설명은 VDA 발행일을 2026-03-19로 서술한다. [사실][^n3] 공식 보도자료 날짜는 2026-04-20이다. [사실][^n4]
- 근거 메모: PDF 표지 “March 2026”; 게시 페이지 날짜 “March 17, 2026”; 릴리스 본문 “March 19th, 2026”; 보도자료 머리 “April 20, 2026”. GitHub API의 `published_at`은 `2026-03-18T19:23:27Z`다. 이는 GitHub 게시 시각이지 표준의 채택일이 아니다. VDA·VDMA·KIT 계열 자료이므로 독립 교차 확인으로 세지 않는다.
- 충돌 처리: 월 단위는 일치하지만 일 단위는 다르다. 3월 17일과 19일의 차이를 시간대만으로 설명할 근거는 없으며, 4월 날짜는 보도자료 날짜다. 위키에는 날짜별 출처를 병기하고 공식 채택일은 확인 못 함으로 남기기를 제안한다. [의견]

### [5. 적용 사례 (현장 유형 명시)] — 수정

**B02. 경로 계산의 책임을 로봇의 주행 방식과 함께 쓴다.**

- 대상 문장 발췌: “경로 계산”. 위치: 본문 5절 수행 자원의 관제 책임 열거.
- 새 내용: VDA 5050 3.0.0의 관제 기능 목록은 경로 계산·유도를 선로 유도형 로봇에 한정해 기술한다. [사실][^n1] 공식 발표는 자유주행형 로봇이 주어진 지점 사이의 상세 경로를 자체 계획하고 관제에 공유하는 구성을 설명한다. [사실][^n4]
- 근거 메모: PDF §5.3 p.11 “line-guided mobile robots”; 보도자료 New features 문단 “detailed route planning takes place on the vehicle itself”. 서로 같은 개발 계열이다. VDA 3.0.0의 역할 설명이며 특정 현장 구현을 검증한 결과가 아니다.
- ROP 시사점: 가상 물류 사례의 전제에 주행 유형과 경로 공유 기능 지원 여부를 적고, 모든 AMR의 상세 경로를 관제가 계산한다고 일반화하지 않기를 제안한다. [의견]

### [6. 대표 접근법과 기술] — 추가

**B03. 프로토콜 판과 구현 제품의 판을 따로 관리한다.**

- 새 내용: `vda-5050-lib.js`의 v1.7.0 변경 이력은 2026-04-29에 VDA 5050 V3.0 지원을 추가했다고 기록한다. [사실][^n5]
- 근거 메모: 태그 고정 CHANGELOG의 `1.7.0 (2026-04-29)`, “VDA5050 V3.0 Support”. 구현 릴리스에 대한 1차 기록이며 실제 제품의 모든 동작 적합성을 증명하지 않는다. VDA 개발 계열과 구현 프로젝트는 별개이지만 동일한 명제를 독립 검증한 것은 아니다.
- ROP 시사점: 로봇별 프로토콜 판, 펌웨어 판, 어댑터 판, 스키마 해시, 지원 동작과 선택 필드를 함께 저장한다. 2.x와 3.x 사이의 명칭 치환만으로 이행을 완료했다고 보지 말고 각 조합별로 회귀 시험한다. [의견][^n1][^n3][^n5]

### [6. 대표 접근법과 기술] — 추가

**B04. 선택 필드와 재전송을 동작 시험으로 구체화한다.**

- 새 내용: 선택 필드라도 로봇 수신자가 임의로 무시해서는 안 된다. [사실][^n1] 동일 주문·갱신 번호의 메시지는 내용이 같을 때와 다를 때 처리 규칙이 다르다. [사실][^n1]
- 근거 메모: PDF §7.1.1 p.67 “shall not ignore”; §6.1.4.5 p.21 “same” / “differs”; §6.1.3.1 p.20, §7.10 p.96. 아래는 이 조항들을 시험으로 옮긴 제안이며 공식 인증 항목 목록은 아니다. [의견]

| 시험 입력 | 관찰할 결과 | 근거 위치 |
|---|---|---|
| 로봇이 지원하지 않는 선택 필드를 포함한 주문 | 주문 거절, `UNSUPPORTED_PARAMETER`와 `CRITICAL` | §6.1.4.2 p.20, §7.1.1 p.67 |
| 현재 주문과 같은 번호·같은 내용의 재전송 | 새 주문 실행 없이 기존 주문 지속 | §6.1.4.5 p.21 |
| 같은 번호지만 내용이 다른 재전송 | `SAME_ORDER_UPDATE_ID`와 `WARNING`, 기존 주문 지속 | 같은 절 |
| 취소된 주문의 후속 갱신 | `ORDER_UPDATE_FOLLOWING_CANCEL`과 `WARNING` | §6.1.3.1 p.20 |

시험 기대값은 위 표의 해당 조항에 근거한다. [사실][^n1] 실행 시에는 수신 직전 주문 상태와 관측 로그의 누락 여부도 보존하기를 제안한다. [의견]

### [7. 관련 표준·프레임워크·오픈소스] — 추가

**B05. 3.0.0 릴리스 스키마의 구문 오류를 재현 가능한 주의사항으로 추가한다.**

- 새 내용: 공식 저장소 이슈 #660은 2026-09-13에 3.0.0 태그의 세 스키마가 유효한 JSON이 아니라고 보고했다. [사실][^n6] 이번 조사에서 그 태그의 `order.schema`, `factsheet.schema`, `visualization.schema`를 내려받아 Python JSON 파서로 검사했을 때 모두 끝 쉼표 오류가 재현됐다. [사실][^n1]
- 근거 메모: 이슈의 Affected files와 Reproduce. 제보 원문의 짧은 구절은 “not valid JSON”. 조사 재현은 원본 파일을 수정하지 않고 수행했다. 이는 구문 검사이며 JSON Schema 전체 의미 검증이나 로봇 적합성 시험은 아니다.

| 태그 파일 | SHA-256 | 이번 재현에서의 오류 위치 |
|---|---|---|
| order.schema | `f7e2d3b5c914e76d28d39e3e5a08b6997e56e9c4cbcceb634f13fe3573986d12` | 314행 130열 |
| factsheet.schema | `d2fd651dc496c4cab34c35b43a3d1293629c3cce954fae71ef6aebbda67991ec` | 173행 32열 |
| visualization.schema | `858eeab4758a5891e1620a8df333e47f341f61dd8d683a41bb0293217ddafc92` | 54행 10열 |

- 제보는 315·174·55행을, 이번 Python 3.14.3 파서는 각각 그 앞 행을 가리켰다. 오류 위치 차이는 파서의 진단 방식 차이로 보이지만 제보자의 실행 환경과 파일 해시를 확인하지 못했다. [추정][^n6] 직접 확인한 구문 오류와 그 원인 해석을 구분한다. 재현 명령과 결과는 부록 D에 남겼다.
- ROP 시사점: ‘공식 태그’와 ‘파싱 가능한 시험 입력’을 별도로 확인한다. 수정 스키마를 사용할 경우 원본과 차이, 수정 근거, 해시를 보존한다. `main`의 내용을 설명 없이 섞지 않는다. [의견]

### [8. 대표 연구와 자료] — 교차 확인

**B06. 공개 진단 도구의 검증 범위를 제한해 소개한다.**

- 대상: 기존 8절의 `vda5050-lab` 소개와 원문 미열람 표시.
- 새 내용: 고정한 커밋의 README는 v0.2.0을 합성 데모 개발자 프리뷰로 설명한다. [사실][^n7] 같은 문서는 실제 고객 로그·외부 시험 대상·실물 하드웨어 검증이 없다고 명시한다. [사실][^n7]
- 근거 메모: README Status의 “Synthetic Demo Preview”, “not a public-alpha or certification claim”, “no real customer trace”, “external DUT”, “hardware execution”. 문서의 자기 기술을 확인했으며 이 조사에서는 프로그램을 실행하지 않았다. 개인 프로젝트의 한계 선언과 공식 시험기관의 인증은 별개다.
- ROP 시사점: 이 도구를 MQTT 로그 진단 보조 후보로 두고, 합격 판정을 구매·연동 승인 전체의 대체물로 쓰지 않기를 제안한다. [의견]

### [6. 대표 접근법과 기술] — 수정

**B07. OPC 자체 시험과 공식 인증을 구별한다.**

- 대상 문장 발췌: “제조사가 자체 인증하거나”. 위치: 분리된 6절 적합성 시험과 인증.
- 새 내용: OPC Foundation은 시험소 인증에 앞서 제조사가 시험 도구로 준비하도록 안내한다. [사실][^n8] 공식 안내는 인증 제품이 인정 시험소의 시험을 거쳤다고 설명한다. [사실][^n20] 인증된 SDK 참조 구현을 사용한 응용도 공식 인증을 위해 자체 제품 시험을 받아야 한다. [사실][^n20]
- 근거 메모: How to Certify, Preparing for Testing의 “before attending” 및 “Certification Lab”; Overview & Benefits의 “require their own certification testing”. 지원 프로파일에 따라 시험 항목이 달라진다. 두 페이지는 같은 기관으로 독립 출처가 아니다.
- 수정 제안: 기존의 자체 인증과 공식 인증이 동등하다는 인상을 주는 구절은 위 문장으로 교체한다. 이 근거를 VDA 5050 인증 체계에 그대로 옮기지 않는다. [의견]

### [7. 관련 표준·프레임워크·오픈소스] — 교차 확인

**B08. MassRobotics 스키마를 직접 확인하고 정보 교환 범위를 한정한다.**

- 대상 문장 발췌: “판·발행일 미확인(원문 미열람)”. 위치: 분리된 7절 표.
- 새 내용: 고정한 `AMR_Interop_Standard.json`의 최상위 `oneOf`는 `identityReport`와 `statusReport`를 참조한다. [사실][^n9] 위치 객체는 `planarDatum`을 필수 필드로 둔다. [사실][^n9]
- 근거 메모: 커밋 `f9357a423ecabc3f7112e6d10025a5231943ec50`의 JSON 최상위와 `definitions.location.required`. 인용 식별자: “identityReport”, “statusReport”, “planarDatum”. 해당 스키마 전체 구조를 확인했으며 별도의 최신 표준 PDF 판·발행일을 확정한 것은 아니다.
- ROP 시사점: 스키마 원문 미열람 표시는 해소하되, 이 보고 메시지 교환만으로 작업 명령 호환성이나 좌표계 정합을 확보했다고 주장하지 않기를 제안한다. [의견]

### [7. 관련 표준·프레임워크·오픈소스] — 추가

**B09. OPC UA Robotics는 정보모델과 프로파일 단위로 비교한다.**

- 새 내용: OPC 40010-1의 공개 목록은 판 1.02와 발행일 2025-09-08을 표시한다. [사실][^n10] 본문은 상위 제어·평가 시스템을 위한 모션 장치 시스템 정보모델을 정의한다. [사실][^n10] §11은 기본·운전·자산관리 확장·상태감시 확장 서버 기능 묶음과 필수·선택 단위를 구분한다. [사실][^n10]
- 근거 메모: 문서 머리, §1, §11.2 표123~127. 짧은 구절: “higher-level control and evaluation systems”, “Mandatory / Optional”. 발행일은 이번 최근 1년 창보다 앞선다. 신규 2026년 표준으로 세지 않는다.
- ROP 시사점: ‘OPC UA 지원’ 대신 정확한 Robotics 판, 서버 기능 묶음, 선택 단위와 인증 범위를 요구한다. 정보모델을 VDA 주문 스키마와 자동으로 일대일 변환할 수 있다는 결론은 내리지 않는다. [의견]

### [7. 관련 표준·프레임워크·오픈소스] — 추가

**B10. ISO 21423의 발행 상태와 제외 범위를 기록한다.**

- 새 내용: 열람 시 ISO 공식 목록은 ISO 21423을 단계 60.00, 발행 준비 중으로 표시한다. [사실][^n11] 범위 설명은 산업용 다사업자 AMR 통신을 대상으로 하고 안전 요구와 공도 운행 이동기계를 제외한다. [사실][^n11]
- 근거 메모: General information 및 Life cycle의 “International Standard under publication”, Abstract의 “Safety-related requirements”와 “public roads”. 발행 월 필드에는 2026-10이 있지만 ‘발행 완료’ 단계 60.60에 날짜가 없다. 표준 본문은 미열람이며 목록의 범위·상태만 확인했다.
- ROP 시사점: 조사일과 단계 코드를 함께 남기고, 구매 규격서에는 본문 발행과 적용 범위 재확인 조건을 두기를 제안한다. [의견]

### [7. 관련 표준·프레임워크·오픈소스] — 추가

**B11. KS B 7321-2와 새로운 부합화 표준을 구분한다.**

- 새 내용: KS B 7321-2 목록은 2024-01-05 제정으로 표시되며 국제표준 부합화 칸은 비어 있다. [사실][^n12] 별도 표준 KS B ISO 22166-202는 2026-09-11 제정이고 ISO 22166-202:2025와 IDT로 표시된다. [사실][^n16] ISO 원표준은 2025년 3월 발행된 소프트웨어 모듈용 정보모델 표준이다. [사실][^n13]
- 근거 메모: 구 KS 이력의 “2024-01-05”, “제정(표준)”; 신규 KS의 “2026-09-11”, “ISO 22166-202:2025(IDT)”; ISO의 “2025-03”, “information models for software modules”. 구 KS의 국제표준 부합화 칸에 값이 없는 것은 화면 구조를 직접 확인했다. 공란을 비부합 또는 폐지의 증거로 쓰지 않는다. 세 표준의 유료 본문은 미열람이다.
- ROP 시사점: oq-026에는 확인 가능한 IDT 표준 번호를 추가하고, 기존 KS와의 대체 관계 및 현장 적용 사례는 별도 미확인으로 남긴다. [의견]

### [7. 관련 표준·프레임워크·오픈소스] — 추가

**B12. KOROS의 제정일·게시일과 후속 TTA 표준을 추가한다.**

- 새 내용: KOROS 1148-8:2025 게시물은 제정일 2025-05-28과 게시일 2025-06-04를 구분한다. [사실][^n14] TTA 공식 목록에는 `TTAK.KO-10.1295-Part8`의 제·개정일이 2026-06-26으로 기재돼 있다. [사실][^n15]
- 근거 메모: KOROS 본문 “표준 제정일”, “2025.05.28.”와 게시 정보 “2025-06-04”; TTA TC4 목록 해당 행 “TTAK.KO-10.1295-Part8”, “2026-06-26”. KOROS는 해당 표준을 바탕으로 TTA 표준이 만들어졌다고 안내한다. 두 기관의 목록은 확인했지만 제정 계열이 연결돼 있으므로 기술 내용의 독립 교차 검증으로 세지 않는다.
- 한계: KOROS 첨부는 성명·소속·이메일과 동의를 요구하는 다운로드 절차여서 본문을 확보하지 않았다. TTA 상세 페이지는 HTTP 400/열람 실패였다. 시험 항목의 동등성 및 VDA 적합성 검사 대체 가능성은 확인 못 했다.
- ROP 시사점: 국내 후보 표준 번호와 날짜는 보강하되, 본문 확보 전에는 플릿 메시지 시험 절차로 채택하지 않기를 제안한다. [의견]

### [6. 대표 접근법과 기술] — 교차 확인

**B13. 기존 공급자 간 인증 발표의 원문과 제품 범위를 보강한다.**

- 대상: 분리된 6절의 OTTO 인증 발표 설명과 해당 각주의 원문 미열람 표시. 공급자 이름과 인증 발표 자체는 이미 위키에 있다.
- 새 내용: OTTO는 2026-04-09 발표에서 OTTO 100·600·1200·1500과 Idealworks·NAiSE·SYNAOS 간 인증을 주장한다. [추정][^n17] 단일 벤더 주장으로 유지한다.
- 근거 메모: 발표 첫 문단 “certified with leading VDA 5050-compliant intralogistics software providers”. 현장 유형은 제조·물류용 제품 연동이다. 본문은 시험 항목, 시험한 프로토콜 판, 독립 시험기관, 성적서와 실물 혼합 플릿 규모를 제시하지 않는다. 공급자 인용문들도 같은 협업 관계이므로 독립 검증으로 세지 않는다.
- ROP 시사점: 발표 존재를 신규 물류센터의 적합성 증명으로 쓰지 말고, 도입 검토 시 실제 제품 조합·펌웨어·시험 범위·성적서를 요청한다. [의견]

### [5. 적용 사례 (현장 유형 명시)] — 추가

**B14. 전시 시연은 실제 배치·관제 교체 검증과 구분한다.**

- 새 내용: VDMA의 Mesh-Up 2025 안내는 9개 참여 기업과 MHP 관제의 생산 공급 시연 구성을 설명한다. [사실][^n18] 같은 안내는 관제 소프트웨어 공급자 선택의 유연성을 현장에서 실시간 시연하지 않는다고 명시한다. [사실][^n18]
- 근거 메모: 본문 소개와 Software 절, “a total of nine companies”, “not demonstrated live”. 행사 기간은 2025-06-24~27이다. 이는 최근 1년 창 밖의 보완 사례이고 안내 문서를 확인한 것이며, 완료 후 실측 성능 보고서는 확보하지 못했다. 기업 수를 로봇 대수로 바꾸지 않았다.
- ROP 시사점: 제조 현장 유형의 전시 구성 사례로만 추가하고, 2026년 최신 실증이나 현장 무중단 관제 교체의 근거로 세지 않는다. [의견]

### [8. 대표 연구와 자료] — 추가

**B15. 2026년 VDA 통신 평가 논문을 실험 조건과 함께 추가한다.**

- 새 내용: Wagner 등은 VDA 5050 원격조작 확장과 트래픽 생성기를 제안했다. [사실][^n19] 평가 시나리오는 단일 모의 로봇의 60초 주문 실행이며, 원격조작 시나리오는 그중 20~40초에 원격조작을 수행한다. [사실][^n19] 연구는 가상 무선 Open RAN 시험과 실제 무선 링크 검증을 구분한다. [사실][^n19]
- 근거 메모: IEEE WFCS 2026 저자 공개본 초록·§III, §IV pp.4~7, 표III·IV, 그림7~10. 짧은 구절은 “proposing”, “traffic generator”, “a single mobile robot”, “60 s”, “20 s to 40 s”, “virtual-radio”, “real-world”, “larger-scale multi-robot scenarios”. 여러 실물 제조사 로봇의 적합성 시험이 아니며 §V의 대규모 다중 로봇 검증은 향후 과제다. 논문에서 제안한 확장을 표준 채택 기능이라고 쓰지 않는다.
- ROP 시사점: 21번 영역에는 통신 부하·지연 평가를 적합성 시험과 구별하는 연구로 소개한다. 상세 네트워크 설계는 10절의 42번 영역 연결 제안으로만 둔다. [의견]

### 스키마 구문 검사 재현

원본 다운로드에는 `curl -fsSL`을 사용했다. 원격 경로는 n1의 `3.0.0/json_schemas/` 아래이며 로컬 파일 내용은 수정하지 않았다. 다음 코드는 저장된 세 파일만 읽는다. Python 3.14.3에서 재실행했고 B05 표와 같은 결과를 얻었다.

```python
from pathlib import Path
import hashlib
import json

root = Path('.research-work/F-21')
for name in ('order', 'factsheet', 'visualization'):
    data = (root / f'f21-{name}.schema').read_bytes()
    print(name, hashlib.sha256(data).hexdigest())
    try:
        json.loads(data)
    except json.JSONDecodeError as error:
        print(error.msg, error.lineno, error.colno)
```

```text
order         Illegal trailing comma before end of object 314 130
factsheet     Illegal trailing comma before end of object 173 32
visualization Illegal trailing comma before end of object 54 10
```

이 검사는 문법 오류의 재현이며 적합성 인증, 메시지 의미 검증, 실제 로봇 동작 시험은 수행하지 않았다.
