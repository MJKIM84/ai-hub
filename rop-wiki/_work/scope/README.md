# 개념 재정립 작업 폴더 (`_work/scope/`)

루프 프롬프트 「개념 재정립: 전체 리스트업·카테고리화·검증·수정 루프」의 A~C 단계 산출물이다. `docs/` 밖에 있어 위키에 게시되지 않는다.

**현재 상태: 멈춤 1 — 사용자 승인 대기.** 승인 전에는 위키 페이지·분류 원문·템플릿·에이전트 규칙을 바꾸지 않는다(프롬프트 12장).

## 파일

| 파일 | 내용 |
|---|---|
| `01_list.md` | A. 리스트업 — ROP를 구현·운영하는 데 관여하는 일 전체(항목 표, 렌즈 점검표) |
| `02_categories.md` | B. 카테고리화 — 영역·카테고리, 필수 두 항목의 위치, 카테고리별 출처 유형 |
| `03_mapping.md` | B. 매핑 — 옛 대분류·세부영역·트랙·아이디어 → 새 구조, 트랙 개편안, 주소 영향, 리다이렉트 목록 |
| `04_verify.md` | C. 검증 6항목, 반복 기록, [가정] 목록 |
| `05_apply.md` | D 수정·E 검증 적용 기록 |
| `data/structure.yaml` | 렌즈, 카테고리, 영역(원천) |
| `data/items_*.yaml` | 항목(원천) |
| `data/mapping.yaml` | 매핑, 트랙 개편안, 주소 정책, [가정](원천) |
| `data/loop_log.yaml` | 검증 반복 기록(원천) |
| `build_scope.py` | 원천을 읽어 01~04를 만들고 검증 6항목을 계산한다. 실패가 있으면 종료 코드 1 |

## 다시 만들기

```sh
python3 rop-wiki/_work/scope/build_scope.py
```

01~04는 생성물이다. 고칠 때는 `data/`를 고치고 다시 생성한다. 항목 수·옛 경로·링크 파일 수·출처 수는 스크립트가 `docs/`를 직접 세서 쓴다.

## 다음 단계

멈춤 1에서 사용자가 정할 것: 이 리스트·카테고리로 구조를 바꿀지(고칠 곳), 트랙 개편안, 주소 정책(안 1 새 경로+리다이렉트 / 안 2 옛 경로 유지).
승인되면 D단계(원문 교체, 페이지 이관 스크립트, 규칙 교체, 트랙, 안내 페이지, 출처 수집 축)를 이 폴더의 `data/`를 입력으로 진행한다.
