# 현장 적용 보완 조사 — A~F

기준 main 9c4de24, 조사 2026-10-13. **공개 원문 관찰**, **발표 내 확인**, **설계 제안**을 구분한다. [사실]의 S 번호는 [sources.md](sources.md)의 원문 구절·절을 가리킨다. 아래 수용 기준은 별도 표기가 없으면 [의견]이며 실험을 수행해 얻은 결과가 아니다.

## A. 현장 준비도

[발표 내 확인] 바닥 오염, 반사체, 명암 변화, 특징 부족, 계단 주변 물체, 파지 공간, 승강기 통신 음영이 실제 적용의 걸림돌로 설명됐다. 발생 빈도·인과·해결 효과는 공개 실증으로 확인되지 않았다.

[사실] NIST의 응급 대응 로봇 시험 방법은 시험 장치·절차·지표를 정의하고, 변수를 통제한 기초 성능에서 환경 조건을 단계적으로 변화시키는 접근을 설명한다(S09, 시험 방법 설명, “Variables are controlled initially”). 응급 대응 시험의 조건이나 등급이 제조·병원 로봇의 합격 기준이라는 뜻은 아니다.

[의견] 준비도는 건물의 단일 점수가 아니라 **작업 × 구간 × 로봇 구성 × 운영 시간대**의 조건부 승인표로 관리한다. 좋은 조명에서 빈 로봇으로 한 번 통과한 기록은 야간·적재·오염 조건의 승인을 대신하지 않는다. 사전 측정 → 제한 구역 반복 시험 → 실제 업무의 감독 운용 → 승인/제한/재시험 순으로 증거를 쌓는다. 이번에는 계획만 제안한다.

|판단 대상|설정 변경 후보|경로·작업 변경 후보|시설 개선 후보|선택을 가르는 조건 [의견]|
|---|---|---|---|---|
|마찰·오염|제조사 허용 범위의 속도·보행/제어 설정|오염 구간 우회, 청소 후 운행|누유 원인 제거·배수·바닥 개선|반복 오염·다른 작업자 위험이면 설정만으로 해결 완료 처리하지 않음|
|반사·투명·명암|지원 센서/노출/조명 옵션|입사각·시간대·관측 위치 변경|검증된 비반사 처리·표지·조명 배치|오검출·미검출을 함께 측정, 감지 기능 해제로 통과율만 높이지 않음|

|계단·문턱·통로|기종/적재별 허용 설정|방향·회전 위치·대기점 변경, 다른 이동 수단|문턱/덮개/동선 개선|안전·피난·설비 접근 기능과 충돌하면 시설 담당 검토 필요|
|무선 음영|지원 통신/로컬 수행 정책|연결 필요한 단계는 음영 밖 배치|AP·백홀·안테나·유선 설비 보완|명령·영상·설비 상태별 요구가 다르므로 RSSI 하나로 합격 금지|

[추정] 벤더 주장: Spot SDK는 지면 마찰 힌트(S06), 특징이 적은 장소의 위치 추정 어려움(S07), LOST와 STUCK 등 상태 구분(S08)을 제공한다. 이 자료는 특정 발표 현장의 원인을 입증하지 않는다.

[의견] 제조 고유 조건에는 절삭유/공정 부산물, 라인 침범, 생산 서열, 치구·허용차, 생산 중단 창을 추가한다. 병원·호텔·공동주택에는 공통으로 사람 혼잡, 승강기 공유, 출입권한, 수령 인계, 소음·촬영을 넣되 병원의 감염구역·검체 인계, 호텔의 객실 프라이버시·서비스 시간, 공동주택의 거주자 동의·관리규약을 별도 열로 둔다. 제조 요구를 그대로 주거 현장에 복사하지 않는다. 측정·담당·비용은 [05](05_decision-matrices.md).

## B. 환경 조건을 반영한 능력 온톨로지

기존 4~7영역과 manual-capability-ontology v0.5의 구성 버전·환경 조건 미완료 질문을 재사용한다([01](01_existing-wiki-gap-matrix.md)). 새 온톨로지를 구현하거나 기존 스키마를 수정하지 않았다.

[사실] W3C SSN은 OperatingRange를 조건 아래의 정상 운용 특성으로 설명한다(S10, §5.1.2.21, “under some specified Conditions”). 센서 조건 어휘를 로봇 배정의 증거 모델에 연결하는 것은 아래 연구 제안이다.

[의견] 하나의 ‘가능=true’ 필드를 다음 세 종류의 주장으로 분해한다.

|종류|기록할 것|갱신·효력|배정에서의 의미|
|---|---|---|---|
|제조사 선언|매뉴얼/SDK 판·구절, 기종·옵션, 한계, 지원 명령|제조사 새 문서에 따라 새 버전 보존|후보 자격의 상한. 현장 성공 증거 아님|
|현장 관찰/검증|기체·센서/도구·FW·설정·지도 버전, 장소·시간·적재·환경, 성공/실패·반복 횟수·기준·로그·검토자|시험 범위/기간에 한정. 구성 변경 시 영향 검토|일치하는 조건의 승인 범위만 사용|
|임시 제한|금지/조건부 허용, 이유·발효/만료·승인자, 구역·작업 범위|만료돼도 자동 성공 승인으로 전환하지 않음|허용 범위를 줄이는 운영 정책. 물리 능력 자체와 구별|

[의견] 연결 모델의 최소 단위는 다음과 같다.

- RobotConfiguration → 기체/센서/도구/FW/설정/적재 인터페이스의 식별·버전.
- CapabilityClaim → 기능·파라미터 범위·전제/유지/사후조건·주장 종류.
- EnvironmentCondition → 바닥/조명/재질/기하/무선/사람 밀도와 측정 방법·불확실성·시각.
- VerificationEvidence → 시험 절차 판, 실측/시뮬레이션/문서 구분, 성공·실패 표본, 원문/로그 위치, 적용 구성, 검토 결과.
- FailureMode → 조건·관측 증상·원인 가설·확정 수준·복구/잔여 제한.
- AssignmentDecision → 작업 요구와 현재 조건의 대조, 근거 ID, 제외 사유, 승인자·시각.

[의견] 질의는 후보 검색과 현장 실행 허용을 나눠 답한다.

|질의 예|반환해야 할 것|
|---|---|
|계단 이동을 지원한다고 선언된 로봇은?|기종·매뉴얼 판·계단 기능 종류·공식 한계. 현장 허용 여부는 별도|
|이 장소의 계단을 이 설정·적재로 지금 내려갈 수 있는가?|그 장소/기하/방향/적재/FW·설정과 일치하는 현장 시험, 현재 상태 신선도, 임시 제한, 승인 유효기간|
|센서 교체 뒤 기존 승인을 쓸 수 있는가?|영향받는 검증 증거 목록과 재시험 필요 이유. 근거 부족이면 ‘확인 필요’|
|실패 사례가 없는 후보는 안전한가?|관찰 횟수·조건 범위·미시험 영역. 실패 없음과 안전 입증을 구분|

[의견] 배정은 선언 범위 ∩ 검증된 현장 범위 ∩ 현재 조건 ∩ 운영 허용 범위 안에서만 제안한다. 미측정·오래된 관측·불일치 구성은 ‘가능’도 ‘불가능’도 아닌 **확인 필요**로 남긴다. 제안 질의는 실행하거나 성능 측정하지 않았다.

## C. 시뮬레이션 재현 한계

[사실] Open-RMF 공식 문서는 slotcar가 단순한 “rail-like” 경유점 이동을 쓰며 교통 관리에 초점을 둔다고 설명한다(S20, Robot plugins). 이 사실을 이 저장소의 별도 MuJoCo 구현 지원 범위로 바꾸지 않는다.

[의견] 두 검증을 분리한다.

1. 사건 주입: 통신 끊김·관측 상실·승강기 지연을 입력해 감지→작업 보류→대체→재개 논리가 맞는지 평가한다.
2. 실패 원인 재현: 오염 접촉, 광학 반사/투과, 위치 추정 알고리즘, RF 전파·핸드오버 등이 실제 센서 출력과 같은 실패를 만드는지 평가한다.

첫 검증에서 복구 성공은 둘째 검증의 인과 정확성을 증명하지 않는다. 물리 엔진/3D 장면은 필요한 모델·센서 파이프라인·현장 보정·검증 자료를 자동으로 제공하지 않는다. 사례별 입력·모델·관측·비교·보정 및 실제 코드 위치는 [06](06_simulation-validation-boundaries.md).

## D. 계층·통신

[발표 내 확인] 서비스/L4~L1은 발표의 설명 체계로만 보존한다. L3와 L2에 제조사 관제 개념이 함께 등장하므로 엄격한 계층 표준으로 확정하지 않는다.

|발표 층|위키 책임 경계에 대응하는 해석 [의견]|결정의 주체|
|---|---|---|
|서비스 MES/WMS|업무 요청·우선순위·인수 기준|업무 소유자가 주문/생산 요구 결정|
|L4 ROP|이종 자원 배정·공용 자원·상위 완료·대체 업무|ROP가 위임받은 범위의 조율; 현장 승인 책임 별도|
|L3 연동/직접 로봇 API|명령·상태·좌표·오류의 어댑터 계약|어댑터 구현자. 단순 중계와 실행 권한 구별|
|L2 RCS/FMS|제조사 플릿 내부 배차·경로·실행 관리|제조사 관제; ROP와 중복 배정/경로 권한 방지|
|L1 로봇·장치|주행·인식·동작·안전 정지|로봇 제어기/제조사|
|별도 시설 제어|문·승강기·PLC 운행 및 안전 인터록|시설 제어기/시설 담당; ROP는 요청·상태 확인|

[사실] VDA 5050은 관제–로봇 통신 명세이며 시설/외부 IT 인터페이스·교통 알고리즘·운영 책임·안전 요구 등을 범위에서 제외한다(S11 §2). 단절 후 마지막 released node까지의 수행을 규정한다(S11 §4.1, 원문 구절 sources 참조). [의견] 따라서 연결 단절을 정지 완료로 해석하거나 VDA 채택만으로 시설 책임이 정해졌다고 해석하지 않는다.

## E. 업무 연속성

기존 29·31·32·43·56영역의 신뢰성·복구·배포·이관 개념을 다음 현장 인계 관문으로 좁힌다.

|단계|증거/결정 [의견]|완료 조건|
|---|---|---|
|정지/격리|물리 정지·적재·설비 점유 확인; 통신 단절만으로 정지 확정 금지|미확인 공간·화물은 점유/확인 대기 처리|
|원인 판단|로봇·환경·통신·시설·관제·업무 오류 분리; 원인 가설과 확정 구별|현재 수행 가능한 제한과 조사 책임자 지정|
|사람/다른 로봇 투입|동일 작업 중복 소유 방지; 대체 능력·접근·적재/도구 확인|대체 담당 수락과 원 수행자의 실행 차단 확인|
|인계|물체/작업/검사 상태, 이동 전후 위치, 수량·식별·책임 수신|발신/수신 증거 일치 또는 사람 확인|
|품질 확인|누락 점검·손상·검체/상품/공정 품질·재고 대조|업무 소유자가 통과/재작업/폐기 판단|
|재개|원인 처리·회귀 검증·임시 제한·최신 구성 승인|재개 승인과 추적 가능한 새 실행 기록|

[의견] 자율 주행, 원격 조작, 원격 리셋, 현장 물리 개입, 수동 대체를 서로 다른 intervention_type으로 기록한다. 리셋 후 자동으로 끝낸 작업도 ‘무개입 성공’으로 계산하지 않는다. 실행시간만큼 개입 대기·처리·재검사를 리드타임에 포함한다.

[의견] 제조사 전달 패키지에는 재현 조건, 기대/실제 결과, 기체·센서·도구·FW/SDK·설정·지도 판, 타임라인/시계 오차, 명령/상태/오류/영상, 발생률과 재현 실패, 변경 전후 결과, 회귀 목록, 롤백 가능 구성과 승인자를 넣는다. 공개용에는 로그의 얼굴·위치·계정·영업 수치를 제거하고 상세 원본은 권한 있는 별도 보관을 제안한다. 이번 작업에서 외부로 원본을 전달하지 않았다.

[의견] **로봇 고장 복구**는 물리 안전·화물·재시동/정비·현장 품질이 관문이다. **관제 SW 연속 배포**는 세션/명령 소유권 이관, 작업 상태 지속성, 호환 가능한 DB/이벤트, 신구 버전 중복 실행 방지와 롤백이 관문이다. 한쪽 성공을 다른 쪽 무중단 증명으로 쓰지 않는다.

## F. 이동 점검·성과

[추정] 벤더 주장: FLIR 측정 문서는 방사율·반사 온도·거리 등 측정 매개변수를 구분한다(S22 Object parameters). 해당 로봇의 카메라/대상에 맞춘 보정 결과는 미확인이다.

[의견] 고정 센서는 지속 관측·고정 위치의 변화를, 이동 센서는 여러 지점의 순회·다른 관측 각도를 담당하도록 설계하되 단순 비용 대체재로 비교하지 않는다. 필요한 탐지 시간보다 재방문 간격이 길거나 대상이 가려지면 이동 점검 성공으로 처리할 수 없다. 로봇이 대상 가까이 도착하는 것과 **유효한 측정**을 얻는 것은 별도다.
