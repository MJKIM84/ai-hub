# 순찰 배송 안내 로봇 서비스를 위한 PM 학습 가이드

**조사일: 2026-10-13 KST. 인터넷 원문 접근: 가능, 일부 실패는 자료집에 기록.**

이 과제의 중심은 로봇 두 종류를 소개하는 데 있지 않다. PM은 **고객에게 어떤 완료 결과를 약속하고, 어떤 현장·기체·시설 조건에서 그 약속을 지키며, 실패했을 때 누가 업무를 이어갈지** 결정해야 한다. 제품 사양, 사용자 흐름, ROP 계약, 현장 인수를 이 결정에 연결해 공부한다.

**[조사용 가정]** 대한민국의 다층 복합 업무빌딩에 로비·사무 공간·공용 복도·승강기·출입통제 구역이 있고 사람과 로봇이 함께 다닌다. 특정 건물의 실측 결과가 아니다. 공장 사례는 비교에 활용하고, 호텔은 야간 소음·객실 사생활·수령 부재의 비교 가설로 다룬다. 실제 기체·현장·예산·수요는 미정이다.

**[최종 제안] 두 항목을 고르면 ① 서비스·사업 모델 + ③ 현장 구축·운영을 추천한다.** 고객 가치와 운영 가능성을 한 흐름으로 입증하기 좋다. ② ROP는 그 약속을 구현하는 책임 경계·시퀀스 한 장으로 뒷받침한다. 플랫폼/기술 PM 면접이라면 ②+③을 주축으로 바꾸고 ①의 완료 정의와 비용을 도입부에 둔다. 어느 조합이든 세 항목의 조사 근거는 아래에 모두 담았다.

## 조사 결과에서 먼저 이해할 것

1. **4휠은 하나의 운동학이 아니다.** Robotnik RB-SUMMIT의 2024 공식 자료에도 skid-steering과 mecanum 구성이 나뉜다. 현재 제품·공개 시뮬레이션 구성과 구매품의 동일성은 별도로 확인해야 한다. [제조사 문서, S01](01_core-materials.md#s01)
2. **4족의 이동과 물체 조작은 다른 능력이다.** Spot의 Arm은 추가 장비이며 전체 페이로드 질량·다리 간섭에 영향을 준다. 계단의 형상·적재·조명·마찰·상하행까지 검증해야 한다. [제조사 문서, S02·03](01_core-materials.md#s03)
3. **제품 자료도 판을 맞춰 읽어야 한다.** Spot 현재 웹과 SDK의 Gamma 설명은 배터리·충전값이 다르고, RB-SUMMIT 현재 HTML과 2024 표도 속도·통신 구성 등이 다르다. 최신 페이지의 숫자와 예전 매뉴얼의 조건을 섞어 단일 사양을 만들지 않는다. [S01](01_core-materials.md#s01), [S02](01_core-materials.md#s02)
4. **빌딩 서비스에는 시설과 기존 업무가 들어간다.** NAVER 1784는 직원 앱·배송·로봇 전용 승강기·ARC를 함께 소개한다. 기존 공용 승강기에 같은 경제성과 운영 결과가 재현된다는 증거는 아니다. [운영기관 보고, S05](01_core-materials.md#s05)
5. **점검 데이터의 품질이 이동 완료보다 중요할 수 있다.** BMW는 시각·열·음향 데이터를 보전에 활용한다고 보고한다. 센서 제조사 매뉴얼은 측정 조건의 중요성을 설명한다. 둘은 특정 건물의 탐지 정확도나 절감액을 보장하지 않는다. [운영기관 보고, S06](01_core-materials.md#s06), [제조사 문서, S18](01_core-materials.md#s18)
6. **ROP는 모든 것을 직접 제어하는 계층이 아니다.** Open-RMF의 조율은 adapter가 제공하는 제어·상태 수준에 의존한다. VDA 5050은 로봇–관제 통신을 다루지만 시설·외부 IT·책임·안전/보안 구현을 모두 해결하지 않는다. [공식 문서, S07·08](01_core-materials.md#s07), [표준, S09](01_core-materials.md#s09)
7. **안전성과 경제성은 현장 조건별 증거가 필요하다.** NIST의 반복·변수 통제 관점, 국내 영상·시설·업무 안전 법령, 고객 합의 목표를 각각 구분한다. 이번 조사는 특정 기체가 이 빌딩에서 안전하거나 수익성이 있다는 실증이 아니다. [S11](01_core-materials.md#s11), [국내 적용 범위](04_deployment-tests-operations.md)

### 실기 SDK를 읽는 보조 연습

주 비교는 RB-SUMMIT과 Spot이지만, 4휠 **Jackal J100**의 공개 API는 ‘제어 API가 있다’와 ‘서비스가 완성됐다’의 차이를 공부하기 좋다.

- [Clearpath Getting Started](https://docs.clearpathrobotics.com/docs/ros/): **ROS 2 Jazzy, 2026-02-11 갱신**, Terminology / Controlling the robot programmatically / Driving the robot / robot.yaml. [제조사 문서] 토픽·액션·서비스로 구성된 API와 `cmd_vel`을 설명하며, 직접 속도 명령이 센서 피드백을 사용하는 자율주행과 다르다는 경고가 있다.
- [Jackal User Manual](https://docs.clearpathrobotics.com/docs_robots/outdoor_robots/jackal/user_manual_jackal/): **2025-08-28 갱신**, Introduction / System Specifications / Safety Considerations. 연구·프로토타이핑 플랫폼이고 별도 센서·자율주행·안전 운영 검토가 필요하다. 공용 로비 투입 추천으로 읽지 않는다.
- [ROS 2 Robot API Overview](https://docs.clearpathrobotics.com/docs/ros/api/overview/): **Jazzy, 개정일 미확인, 접근2026-10-13**, 공식 API 구조. 이 보조 예제의 토픽을 Robotnik 실기 인터페이스로 복사하지 않는다.

연습 질문: “속도 명령을 보냈다는 기록만으로 배송 완료를 판단할 수 있는가?” 답은 아니며, 위치·진행·인계 증거와 상위 상태 계약이 필요하다. 이 조사에서는 명령·코드·시뮬레이션을 실행하지 않았다. 잘못 추정한 `/docs/ros/robot_navigation/` 경로는 열람 실패하여 내용에 사용하지 않았다.

### 1주 사례와 설계 및 시험 심화

예시 **하루 3시간, 총 21시간**. 문서·인터뷰 준비·모의 검토 중심이며 현장 운전은 별도 승인된 전문팀의 일정이다.

## E 발표 적용 제안

### 두 항목 조합

|조합|설득력 있는 지점|빠지기 쉬운 것|권장 대상|
|---|---|---|---|
|**① 서비스·사업 + ③ 구축·운영**|고객 가치→실제 운영 조건→비용·인수로 연결|ROP가 단순 ‘관제 화면’으로 보일 수 있으므로 책임/시퀀스 한 장 보충|**이번 요청의 기본 추천**, 서비스·사업·제품 PM|
|② 아키텍처 + ③ 구축·운영|분산 연동의 실패와 현장 검증을 구체적으로 연결|사용자 가치·경제성이 빠질 수 있으므로 완료 정의·비용 표 보충|플랫폼/솔루션/기술 PM|
|① 서비스·사업 + ② 아키텍처|요청·상태·사용자 경험을 시스템 계약으로 연결|시설 가능성·인수/유지보수 부담을 놓치기 쉬움|서비스 플랫폼 PM, 기존 구축 인프라가 확보된 경우|

**주장할 제안의 범위:** 평탄부 배송·안내를 4휠 중심으로 검토하고, 계단·비정형 접근의 점검 공백이 확인되는 경우 4족을 추가 비교한다. 한 종류 또는 사람/고정 센서만으로 충분하면 이종 로봇을 도입하지 않는다. 근거는 제품의 조건부 기능, 빌딩 통합 사례, 점검 운영 사례이며 ROI와 안전성은 시범으로 검증할 가설이다.

### 세 항목을 연결하는 발표 구성 예시

**15분, 9장**의 준비 틀이다. 발표 문구의 완성본이 아니라 근거 배치안이다.

|2 · 2분|왜 이 서비스·기종 조합인가|4휠/4족 적합성, 단일 기종/사람 대안, S01~03|

|4 · 1.5분|누가 비용을 내고 어떻게 효과를 보나|TCO와 시나리오별 ROI. 가상 수치와 실제 견적 구분|
