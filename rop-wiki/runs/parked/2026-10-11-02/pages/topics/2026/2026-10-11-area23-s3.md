# 23. 업무 시스템 연동 — 왜 중요한가

<!-- auto:page-status:start -->
<!-- auto:page-status:end -->

## 1. 세 줄 요약

- 로봇 관제 인터페이스 표준인 VDA 5050 3.0.0은 관제(fleet control)와 이동로봇 사이의 통신만 다루고, 외부 IT 시스템 같은 다른 인터페이스와 교통 관리 로직은 범위 밖에 둔다(2026-09-25 확인). [사실][^ref-031] 그래서 ERP·WMS·MES 같은 상위 시스템의 주문과 변경을 로봇 작업으로 옮기는 일은 로봇 표준이 대신해 주지 않는다.
- 이 페이지는 [23. 업무 시스템 연동](../../categories/integration/business-system-integration.md) 페이지의 "왜 중요한가" 절이 분량 기준을 넘어 옮겨 온 것이다. 원 페이지의 검증을 거친 내용이며 새 주장은 없다.

## 2. 배경

[23. 업무 시스템 연동](../../categories/integration/business-system-integration.md) 페이지를 쓰는 과정에서 "왜 중요한가" 절의 분량이 세부영역 페이지 기준(4,000자)을 넘어, 내용을 줄이지 않고 이 주제 페이지로 분리했다.

## 3. 본문

로봇 관제 인터페이스 표준인 VDA 5050 3.0.0은 관제(fleet control)와 이동로봇 사이의 통신만 다루고, 외부 IT 시스템 같은 다른 인터페이스와 교통 관리 로직은 범위 밖에 둔다(2026-09-25 확인). [사실][^ref-031] 그래서 ERP·WMS·MES 같은 상위 시스템의 주문과 변경을 로봇 작업으로 옮기는 일은 로봇 표준이 대신해 주지 않는다.


### 2026-10-11 보탠 내용과 정정

업무 시스템 쪽의 변경도 작업 상태에 묶여 있다. OPC UA for ISA-95 Job Control 2.00.0 은 아직 시작하지 않은 작업 지시만 Update 로 갱신하고 [사실][^ref-131], Oracle WMS Cloud 26c 의 우선순위 변경 API 는 Ready·Held·Created 상태인 작업의 우선순위만 바꿀 수 있게 한다(2026-10-11 확인). [사실][^ref-1457] 구축자 의견으로는 우선순위 변경·취소 같은 요청의 허용 여부를 업무 작업 상태와 로봇 실행 단계에 대해 따로 검사해야 하므로, 로봇 표준과 별도로 두 상태를 잇는 번역이 필요해 보인다. [의견][^ref-131][^ref-1457]

**정정(2026-10-11).** 위 주제 페이지의 ‘확인한 연동 사례는 자체 REST·MQTT 인터페이스를 썼다’는 서술은 근거 논문의 원문과 다르다. Lopes 외(Applied Sciences, 2025-06-27)의 GreenAuto 사례는 MES·ERP 용 REST API, AMR 실시간 이벤트·IIoT 용 MQTT broker, VDA 5050 연동을 모두 미래 확장 계획(당시 미가동)으로 두고, 플릿 관리 시스템과 IIoT 시스템의 통신이 당시 구현에서 아직 활성화되지 않았다고 밝히므로 업무 시스템 연동이 가동된 사례로 볼 수 없다. [사실][^ref-136]
