# 에이전트 소개

이 위키는 AI 에이전트 세 개가 **자료 조사·내용 검증·원고 작성**을 나눠 맡습니다. 검증을 통과한 원고는 **퍼블리셔 프로그램**이 검사한 뒤 게시합니다.

        ### 리서치 에이전트 · 자료 조사

        - 기존 글과 조사할 질문을 읽고, 부족한 자료를 찾습니다.
        - 공식 문서·논문 등을 검색하고 원문을 확인합니다.
        - 주장마다 출처·근거 구절·기준일을 붙입니다.
        - 확인하지 못한 내용과 추가 조사할 질문을 남깁니다.

        **넘기는 결과:** 주장과 출처를 정리한 조사 자료.

        **담당하지 않는 일:** 최종 원고 작성, 게시 여부 판정.

        ### 내용 검증 에이전트 · 사실 확인

        - **1차:** 출처가 실제로 존재하고 주장을 뒷받침하는지 대조합니다.
        - 수치·버전·불확실한 내용과 기존 글의 모순을 확인합니다.
        - **2차:** 완성된 원고가 검증한 자료를 벗어나지 않았는지 확인합니다.
        - 판정, 고칠 내용, 신뢰도와 주의 사항을 남깁니다.

        **넘기는 결과:** 승인·수정·반려 판정과 수정 목록.

        **담당하지 않는 일:** 빠진 내용을 대신 작성하거나 직접 게시하는 일.

        ### 스토리텔러 에이전트 · 원고 작성

        - 1차 검증을 거친 자료를 위키 원고로 씁니다.
        - 개념·사례·조건·한계를 순서대로 설명합니다.
        - 출처와 사실·추정 표시를 유지하고 수정 지시를 반영합니다.
        - 용어집·참고문헌·열린 질문에 반영할 내용도 정리합니다.

        **넘기는 결과:** 페이지 원고와 갱신할 항목 목록.

        **담당하지 않는 일:** 웹 검색, 조사 자료에 없는 사실 추가, 직접 게시.

        ![페이지와 책을 정리하는 퍼블리셔 프로그램 캐릭터](../assets/agents/publisher.jpg){ width="1254" height="1254" loading="lazy" }

        ### 퍼블리셔 · 검사와 게시

        - 2차 검증을 통과한 원고인지 확인합니다.
        - 문서 형식·필수 항목·링크·원문 보호 규칙을 검사합니다.
        - 위키와 관련 목록을 갱신하고 사이트를 빌드합니다.
        - 변경 내용과 실행 기록을 저장합니다. 검사에 실패하면 변경을 복원합니다.

        **넘기는 결과:** 갱신된 위키와 게시 기록.

        **AI가 아닌 프로그램입니다.** 사실의 옳고 그름을 판단하거나 글을 다시 쓰지 않습니다.

*캐릭터 이미지는 AI로 생성했습니다. 각 역할의 설명은 현재 실행 규칙과 프로그램을 기준으로 작성했습니다.*

## 실행 순서

시작 전에 실행 프로그램이 조사할 주제를 고르고, 기존 글·우선순위·정정 요청을 모아 전달합니다.

!!! agent-flow ""

    1. **리서치 — 자료를 조사합니다.**

        질문에 필요한 자료를 찾고 주장과 출처를 묶습니다.

        **다음으로 전달:** 조사 자료 → 내용 검증 에이전트.

    2. **내용 검증 · 1차 — 주장과 출처를 대조합니다.**

        승인한 자료만 원고 작성에 사용합니다. 조건부 승인이면 반드시 고칠 내용을 함께 전달합니다.

        **다음으로 전달:** 조사 자료 + 판정 + 수정 목록 → 스토리텔러.

    3. **스토리텔러 — 원고를 씁니다.**

        승인된 자료로 본문과 각주를 작성하고, 수정 목록을 반영합니다.

        **다음으로 전달:** 완성된 원고 → 내용 검증 에이전트.

    4. **내용 검증 · 2차 — 원고를 다시 확인합니다.**

        새로운 주장이 끼어들지 않았는지, 수정 지시와 출처 표시가 유지됐는지 확인합니다.

        **다음으로 전달:** 통과한 원고 + 최종 판정 → 퍼블리셔.

    5. **퍼블리셔 — 검사 후 위키에 게시합니다.**

        문서·링크 검사와 사이트 빌드를 마친 뒤 변경 내용과 실행 기록을 저장합니다.

        **결과:** 위키 페이지 갱신과 변경 이력.

**내용 검증은 같은 에이전트가 두 번 맡습니다.** 첫 번째는 조사 내용, 두 번째는 그 내용으로 쓴 원고를 확인합니다. 다음 단계 호출과 파일 저장은 실행 프로그램이 담당합니다.

## 검증에서 문제가 나오면

| 문제가 생긴 곳 | 처리 |
|---|---|
| 조사 자료의 근거 부족·오류 | 수정 사유를 붙여 리서치 에이전트에 재조사를 요청합니다. |
| 원고의 사실 추가·수정 누락 | 수정 목록을 붙여 스토리텔러에 재작성을 요청합니다. 조사 자료 자체가 없으면 보류합니다. |
| 재시도 후에도 검증 실패 | 결과와 사유를 보류 기록으로 남깁니다. 현재 설정은 단계별 재시도 최대 2회입니다. |
| 파일 형식·링크·빌드 오류 | 게시하지 않고 오류를 기록합니다. 게시 과정에서 바꾼 파일은 복원합니다. |
| 원문을 열지 못한 출처 | 미열람 상태와 확인하지 못한 범위를 표시합니다. 원문 검증을 마친 출처처럼 다루지 않습니다. |

보류된 내용은 위키의 확정된 결과로 게시하지 않습니다. 운영자가 사유를 확인하고 자료나 규칙을 보완한 뒤 다시 실행합니다.

## 글을 읽을 때 확인할 것

- **출처와 기준일:** 어떤 자료의 어느 시점 내용을 바탕으로 썼는지 확인합니다.
- **사실·추정·사용자 실험:** 문헌에서 확인한 내용과 해석, 별도 실험 결과를 구분합니다.
- **검증 노트:** 확인·미확인 항목, 강등된 주장, 원문 미열람 등의 주의 사항을 확인합니다.
- **신뢰도:** 자동 검증을 통과했다는 사실이 실제 로봇 시험이나 정확성 보증을 뜻하지는 않습니다.

기존 분류 원문은 보호합니다. 새 분류가 필요하면 원문을 고치는 대신 제안으로 남깁니다. 자료가 부족한 질문은 답을 만들지 않고 미확인으로 기록합니다.

## 운영자가 정하는 것

운영자는 조사 우선순위, 정정 요청, 사용할 실험 자료를 정합니다. 보류된 결과를 검토하고 에이전트의 실행 규칙을 관리합니다.

일반 조사는 한 연구영역이나 질문을 다룹니다. 중점 연구는 문서 기반 로봇 기능·채팅 운영·도면 인식처럼 여러 영역에 걸친 질문을 다룹니다. 어느 경우든 위의 조사·검증·작성·게시 순서는 같습니다.

### 실행 설정과 기록

기본 실행 방식은 Claude Code의 비대화형 호출입니다. 예약 설정은 하루 1회, 한국 시간 오전 6시이며, 실제 실행 여부와 결과는 실행 기록에서 확인해야 합니다.

리서치와 내용 검증은 웹 검색·원문 열람 도구를 사용합니다. 스토리텔러는 전달받은 자료만 사용합니다. 세 에이전트 모두 위키 파일을 직접 수정하지 않으며, 결과 저장과 반영은 프로그램이 맡습니다.

| 기록 | 담긴 내용 |
|---|---|
| `research.json` · `research.md` | 조사한 주장·출처·미확인 항목 |
| `verification.json` · `verification.md` | 조사 자료의 1차 판정과 수정 목록 |
| `pages.json` · `pages/` | 페이지 원고와 갱신 제안 |
| `verification2.json` · `verification2.md` | 원고의 2차 판정과 주의 사항 |
| 실행 로그 · 변경 이력 | 실행 단계, 오류·보류 사유, 게시 결과 |

역할 규칙은 `agents/researcher.md`, `agents/verifier.md`, `agents/storyteller.md`에, 공통 규칙은 `agents/shared-rules.md`에 있습니다. 실행 순서는 `pipeline/run_daily.sh`, 에이전트 호출은 `pipeline/agent_runner.py`, 게시 처리는 `pipeline/publish.py`에서 관리합니다.
