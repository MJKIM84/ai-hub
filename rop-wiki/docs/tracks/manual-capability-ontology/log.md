# 트랙 로그 — 매뉴얼 기반 로봇 기능 온톨로지

이 로그는 중점 연구 트랙 [매뉴얼 기반 로봇 기능 온톨로지](index.md)의 실행마다 무엇을 답했고, 어떤 질문이 새로 생겼고, [능력 온톨로지 초안](ontology-draft.md)이 어떻게 바뀌었고, 단계 완료 조건이 어떻게 평가됐는지를 기록한다. 항목은 트랙 실행마다 하나씩 추가된다. 갱신 주체는 퍼블리셔 스크립트이지만(빌드 사양서 4.6), 이 페이지를 자동으로 다시 쓰는 렌더러는 아직 파이프라인에 없어 추가 예정이다("항목 형식" 절 끝 참고). 질문의 현재 상태는 [질문 백로그](question-backlog.md)에, 실행 전체의 단계별 결과·소요 시간·예산 사용량은 그날의 일일 로그에 있다.

## 항목 형식

실행마다 "실행 <실행 id> — 단계 <번호>. <이름>" 소제목 하나와 여덟 항목 표 하나를 둔다. 여덟 항목은 사양서 5.4의 트랙 로그 항목이다.

| 항목 | 내용 |
|---|---|
| 실행 id | 트랙 실행의 id(예 `2026-09-26-01`)와 그날의 일일 로그 링크. 구축 시드는 `build-2026-09-24` |
| 단계 | 그 실행이 다룬 단계. 번호와 이름을 함께 쓰고 단계 페이지에 링크한다 |
| 답한 질문 | 질문 id, 질문 앞부분, 답 위치 링크. 없으면 "없음"과 이유 |
| 새 질문 | 질문 id, 질문 문장, 보낸 단계(번호와 이름), 근거 finding id. 없으면 "없음"과 이유 |
| 온톨로지 변경 | 버전 변화(예 v0 → v0.1)와 추가·변경·폐기된 개념·관계, 근거 finding id, 검증 승인 여부. 승인되지 않은 제안은 "보류"로 적는다. 없으면 "변경 없음"과 이유 |
| 완료 조건 평가 | 리서치 에이전트의 자체 평가, 내용 검증 에이전트의 판정, 단계 전환 여부 |
| 세부영역 반영 제안 | 관련 세부영역(번호와 이름)의 어느 절에 무엇을 반영하자는 제안(`pages.json`의 `area_reflection_proposals`). 없으면 "없음" |
| 다음 실행 제안 | 다음에 다룰 질문 id(우선순위 순), 되돌아온 앞 단계 질문, 사용자에게 요청할 것, 예산·환경 메모 |

항목은 최신순으로 쌓인다(가장 최근 실행이 맨 위). "실행 기록" 절의 본문은 자동 갱신 영역(auto 마커, 키 `track-log`)으로 묶어 두었다. 다만 `track-log`는 공통 규약의 auto 키 목록에 없는 키이고, 퍼블리셔의 키 목록(`pipeline/lib/autoregion.py`의 `AUTO_KEYS`)과 렌더러(`pipeline/lib/render.py`의 `render_for`)에도 등록되어 있지 않다. 따라서 현재는 어떤 스크립트도 이 영역을 다시 쓰지 않으며, 퍼블리셔가 트랙 실행마다 항목을 자동으로 추가하는 기능은 추가 예정이다. 추가 방식의 기본안은 스토리텔러 에이전트가 `pages.json`의 `track_updates.log_entry`로 낸 내용을 퍼블리셔가 `verification.json`(단계 완료 판정·전환 승인)과 `research.json`의 `track` 블록으로 보완해 원천 데이터 `data/tracks/manual-capability-ontology/log.json`에 항목으로 추가하고, 그 파일에서 이 영역을 최신순으로 다시 만드는 것이다. 구축 시드 항목(build-2026-09-24)은 그 파일에도 같은 내용으로 들어 있다. 렌더러가 추가되기 전까지는 이 페이지의 표가 기준이며, `log.json`은 어떤 스크립트도 읽지 않는 같은 내용의 사본이므로 둘을 함께 고쳐야 한다. [가정] 이 페이지에는 사실 태그를 붙이지 않는다(운영 기록). [가정]
