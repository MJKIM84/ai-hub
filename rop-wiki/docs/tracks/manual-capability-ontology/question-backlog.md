# 질문 백로그

이 페이지는 중점 연구 트랙 [매뉴얼 기반 로봇 기능 온톨로지](index.md) 전용의 열린 질문 목록이다. 위키 전체의 [열린 질문](../../open-questions.md)에는 이 백로그로 가는 링크와 열린 질문 수만 두고, 트랙 질문 자체는 여기에 둔다. 원천 데이터는 `data/tracks/manual-capability-ontology/backlog.json`이며, 아래 목록 표는 퍼블리셔가 그 파일에서 자동으로 만든다.

시드는 트랙 정의(빌드 사양서 8.1)의 시작 질문 31개다. 단계 1에 6개, 단계 2에 5개, 단계 3에 6개, 단계 4에 5개, 단계 5에 4개, 단계 6에 4개, 단계 7에 1개이며, 질문 문장은 괄호 안의 출처 후보까지 트랙 정의 그대로다. 단계 7의 시작 질문은 트랙 정의에 번호 없는 한 문단(물음표 두 개)으로 적혀 있어 하나의 질문(q7-01)으로 등록했다. 두 물음은 같은 시나리오 4종의 결과를 묻는 것이어서 나누지 않았다. [가정] 괄호 안 이름은 리서치 에이전트가 실재·최신성을 확인해야 할 출처 후보이지, 확인된 출처가 아니다.

시드 질문 가운데 q1-06, q4-03, q4-04, q7-01은 세부영역을 "5번", "13번"처럼 번호로만 부르고 "부록 A"라는 이름을 쓴다. 트랙 정의 원문을 그대로 옮긴 것이며 문장을 고치지 않았다. "부록 A"는 이 위키의 분류 원문(`_source/ROP_SCM_연구분야_분류.md`)을 뜻하고, 번호는 다음 세부영역이다: [5. 로봇 능력·작업 온톨로지](../../categories/b-common-information-and-environment-model/05-robot-capability-and-task-ontology.md), [8. 실시간 세계 상태·데이터 일관성](../../categories/b-common-information-and-environment-model/08-real-time-world-state-and-data-consistency.md), [9. 로봇·제조사 관제 연동](../../categories/c-connectivity-and-execution-foundation/09-robot-and-vendor-fleet-manager-integration.md), [12. 명령·작업 실행의 신뢰성](../../categories/c-connectivity-and-execution-foundation/12-command-and-task-execution-reliability.md), [13. 작업 배정 — MRTA](../../categories/d-planning-and-optimization/13-task-allocation-mrta.md), [21. 온보딩·설정·현장 시운전](../../categories/f-deployment-verification-and-maintenance/21-onboarding-configuration-and-commissioning.md), [25. 안전·위험 관리](../../categories/g-safety-security-intelligence-and-governance/25-safety-and-risk-management.md). "부록 A 11장의 여섯 항목"은 [SCM 관점의 연구 시작 방법](../../about/research-method.md)의 여섯 항목(시작 조건, 작업 대상, 수행 자원, 제약, 완료·인계, 예외·성과)이다.

**확장 아이디어 1 편입으로 더한 질문(2026-09-25).** 사용자가 제안한 [아이디어 1. 로봇 기능 온톨로지](../../ideas/robot-capability-ontology.md)의 시작 질문과 새 연구 목표 4(작업 할당 질의)·5(신규 로봇 온보딩 시 능력 정의 초안 자동 생성)의 질문 6개를 제기 근거 `사용자`로 더했다: q3-07·q3-08(단계 3. 비정형 문서에서 온톨로지를 추출하는 방법 조사), q4-07·q4-08(단계 4. 온톨로지를 실행에 연결하는 방법 조사), q5-06(단계 5. 완전성과 정확성을 검증하는 방법 조사), q7-02(단계 7. ROP 활용 시나리오 종합과 가설 판정). q3-07과 q4-07은 사용자 요청의 문구 그대로다. 요청의 첫 질문 "로봇 능력을 표현하는 기존 온톨로지·표준은 무엇이 있는가"는 q1-01과 같은 질문이라 새 id를 만들지 않고 q1-01에 대응시켰다(q1-01은 실행 2026-09-25-02에서 답함). 같은 목록이 아이디어 페이지의 "7. 미해결 질문 백로그"에 상태순으로 실린다. ## 항목 형식

항목 형식은 사양서 8.2 "백로그 항목 형식"을 따른다. 아래 표는 각 항목의 필드와 `backlog.json`의 키를 대응시킨 것이다.

| 항목 | JSON 키 | 값 |
|---|---|---|
| id | `id` | `q<단계>-<두 자리>` 형식. 예: `q1-01`. 단계 안에서 번호순으로 매기며 한 번 부여한 id는 재사용하지 않는다 |
| 질문 | `question` | 질문 문장. 시드는 트랙 정의 그대로, 이후 질문은 리서치 에이전트가 제안하고 내용 검증 에이전트가 중복·단계 태그를 확인한 문장 |
| 단계 | `stage` | 1~7. 뒤 단계에서 앞 단계의 질문이 생기면 앞 단계 번호를 붙인다 |
| 제기 근거 | `origin` | finding id(예 `f3`, 제안한 실행의 발견 사항) 또는 `사용자`. 시드 질문 31개는 사용자가 정의한 트랙 정의의 시작 질문이므로 `사용자`로 적었다. `config/priority.yaml`의 `track_questions`로 넣은 질문도 `사용자`이며, 둘은 제기일과 id로 구분한다. [가정] |
| 상태 | `status` | 열림 / 조사 중 / 답함 / 보류 / 폐기 |
| 답한 실행 id | `answered_run_id` | 답한 트랙 실행의 id(예 `2026-09-26-01`). 답하기 전에는 `null` |
| 답이 실린 페이지 링크 | `answer_link` | 저장소 루트 기준 경로와 앵커(예 `docs/tracks/manual-capability-ontology/stage-1-existing-models-and-standards.md#q1-01`). 답하기 전에는 `null` |
| 제기일 | `created` | YYYY-MM-DD |

상태의 뜻은 다음과 같다. **열림**은 아직 다루지 않은 질문, **조사 중**은 이번 실행의 대상으로 선정되어 답을 찾는 중인 질문, **답함**은 내용 검증 에이전트가 승인한 답이 단계 페이지(또는 주제 페이지)에 실린 질문, **보류**는 출처를 찾지 못했거나 사용자 입력(실험 결과, 자료)이 필요해 잠시 멈춘 질문, **폐기**는 중복이거나 트랙 범위 밖으로 판정된 질문이다. 폐기한 질문은 목록에서 지우지 않고 상태만 바꾼다.

## 질문이 오가는 흐름

1. **선정.** 트랙 실행마다 현재 단계의 열린 질문 중 1~3개를 고른다. 순서는 빌드 사양서 6.1의 규칙대로 사용자 지정(`track_questions`) → 앞 단계로 되돌아온 질문 → 오래된 순이다. "오래된 순"은 제기일(`created`)이 이른 순, 같은 날이면 id 순으로 본다. [가정] 대상 선정 스크립트가 이 순서로 후보 질문 id를 `target.json`에 넣고, 리서치 에이전트가 그 안에서 답할 질문을 정한다. [가정]
2. **답과 후속 질문.** 리서치 에이전트가 질문마다 답·근거·신뢰도·후속 질문을 낸다. 후속 질문에는 단계 태그와 근거 finding id가 붙는다.
3. **확정.** 내용 검증 에이전트가 답의 근거를 검증하고, 새 질문이 기존 백로그와 중복되지 않는지와 단계 태그가 맞는지 확인한다.
4. **반영.** 스토리텔러 에이전트가 단계 페이지의 질문 목록과 조사 결과를 갱신하고 상태 변경을 `pages.json`의 `track_updates.backlog_updates`로 낸다. 퍼블리셔가 `backlog.json`을 고치고 이 페이지의 목록 표와 [트랙 개요](index.md)의 단계 진행 현황, 홈의 트랙 현황을 다시 만든다.
5. **되돌아오기.** 뒤 단계에서 생긴 앞 단계의 질문은 앞 단계 태그로 들어가 다음 트랙 실행에서 우선 처리된다. 그 단계의 상태는 "재개"가 된다.

답한 질문의 답은 해당 단계 페이지의 "3. 조사 결과" 아래 질문 id로 시작하는 소제목에 실린다. 단계 페이지는 [트랙 개요](index.md)의 단계 진행 현황에서 찾을 수 있다.

## 우선순위 올리기: `config/priority.yaml`의 `track_questions`

사용자는 백로그에 질문을 넣거나 기존 질문을 먼저 다루게 하고 싶을 때 `config/priority.yaml`의 `track_questions`에 항목을 적는다. 항목 형식은 다음과 같다.

```yaml
track_questions:
  - track: manual-capability-ontology   # 트랙 slug
    stage: 1                            # 질문을 넣을 단계 번호(1~7)
    question: "산업 상호운용 규격의 팩트시트는 적재 제약을 어떤 필드로 기술하는가?"
    priority: high                      # high | normal | low [가정]
```

처리 규칙은 다음과 같다.

- 다음 트랙 실행에서 이 질문이 가장 먼저 선정된다. 지정한 단계가 현재 단계와 다르면 그 단계 태그로 백로그에 들어가고, 앞 단계면 되돌아온 질문과 같이 우선 처리된다. [가정]
- 백로그에 들어갈 때 제기 근거는 `사용자`, id는 그 단계의 다음 번호(예: 단계 1이면 `q1-07`)로 매겨진다. 기존 질문과 같은 내용이면 내용 검증 에이전트가 중복으로 판정하고 기존 질문의 우선순위만 올린다. [가정]
- 우선 지정은 조사 순서를 정할 뿐 검증 규칙을 바꾸지 않는다. 출처가 확인되지 않은 답은 게시되지 않는다.
- 처리된 항목은 `priority.yaml`에서 지워도 된다. 지우지 않으면 계속 우선순위가 유지된다.

정정 요청과 실험 결과 입력 등 다른 개입 방법은 [기여·정정 방법](../../about/how-to-contribute.md)에 있다.
