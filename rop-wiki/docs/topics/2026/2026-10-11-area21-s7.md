# 21. 상호운용 표준·적합성 — 관련 표준·프레임워크·오픈소스

## 1. 세 줄 요약

- 이 영역의 표준은 로봇–관제 규격, 변경 알림 규칙, 적합성 시험, 감사·서비스 관리, 국내 표준으로 나뉜다. [의견] 2026-09-25 에 쓴 표준 비교표와 이전 내용은 [21. 상호운용 표준·적합성 — 관련 표준·프레임워크·오픈소스 (2026-09-25)](2026-09-25-area28-s7.md)에 있고 그 페이지의 정정은 다음 갱신 실행으로 넘겼으며, 전체 목록은 [표준·프레임워크 목록](../../standards/index.md)에 있다.
- 이 페이지는 [21. 상호운용 표준·적합성](../../categories/integration/interoperability-standards-and-conformance.md) 페이지의 "관련 표준·프레임워크·오픈소스" 절이 분량 기준을 넘어 옮겨 온 것이다. 원 페이지의 검증을 거친 내용이며 새 주장은 없다.

## 2. 배경

[21. 상호운용 표준·적합성](../../categories/integration/interoperability-standards-and-conformance.md) 페이지를 쓰는 과정에서 "관련 표준·프레임워크·오픈소스" 절의 분량이 세부영역 페이지 기준(4,000자)을 넘어, 내용을 줄이지 않고 이 주제 페이지로 분리했다.

## 3. 본문

이 영역의 표준은 로봇–관제 규격, 변경 알림 규칙, 적합성 시험, 감사·서비스 관리, 국내 표준으로 나뉜다. [의견] 2026-09-25 에 쓴 표준 비교표와 이전 내용은 [21. 상호운용 표준·적합성 — 관련 표준·프레임워크·오픈소스 (2026-09-25)](2026-09-25-area28-s7.md)에 있고 그 페이지의 정정은 다음 갱신 실행으로 넘겼으며, 전체 목록은 [표준·프레임워크 목록](../../standards/index.md)에 있다.

아래 소절은 2026-10-11 실행에서 보태거나 바로잡은 내용이다.

### VDA 5050 3.0.0 의 판과 날짜

[VDA 5050](../../glossary/vda-5050.md) 공식 저장소의 3.0.0 명세 마크다운 표지는 판을 'Version 3.0.0'으로만 적고 날짜를 적지 않는다(2026-10-11 확인). [사실][^ref-031] [2026-09-25 표준 표](2026-09-25-area28-s7.md)의 VDA 5050 행 발행일은 단일 날짜로 확정하지 않고 '미확인'으로 두되, VDA 발행물 카탈로그의 표시일(2026-03-17)과 3.0 발표 보도자료의 날짜(2026-04-20)가 서로 다르다는 점은 [20. 로봇·제조사 관제 연동 — 관련 표준·프레임워크·오픈소스](2026-10-10-area20-s7.md)의 「VDA 5050 3.0.0의 날짜 표시」 부분으로 연결하는 것이 맞다. [의견][^ref-1412][^ref-032][^ref-031] 3.0.0 작업에 참여했다고 밝힌 업체 Idealworks 는 2026년 3월 소식 글에서 VDMA·VDA 가 2026-02-17 에 3.0.0 판을 정식 채택했고 이어 법적 승인 절차를 거쳤다고 적어, VDA 자료의 날짜 표시와 또 다른 날짜를 제시한다. 이는 업체 서술이며 VDA 자료로는 확인되지 않았다. [추정][^ref-1429] 세 날짜는 한쪽을 고르지 않고 함께 두며, oq-005 에 출처 충돌로 올린다.

### 공식 태그의 JSON 스키마를 시험 입력으로 쓸 때

공식 저장소 3.0.0 태그의 [JSON 스키마](../../glossary/json-schema.md) 가운데 주문(order)·팩트시트(factsheet)·시각화(visualization) 스키마에는 닫는 괄호 바로 앞에 쉼표가 오는 끝 쉼표(trailing comma)가 있어 엄격한 JSON 으로 읽히지 않는다(2026-10-11 확인). [사실][^ref-1414][^ref-1418][^ref-1420] main 브랜치의 주문 스키마는 같은 자리에 끝 쉼표가 없다. [사실][^ref-413] 두 관찰은 스키마 파일의 구문에 관한 것이며 로봇 적합성 시험 결과가 아니다. [의견] 3.0.0 을 시험 입력으로 쓸 때는 '공식 태그'와 '파싱 가능한 시험 입력'을 따로 확인하고, 수정한 스키마를 쓰면 원본과의 차이·수정 근거·해시를 보존하며, main 브랜치 내용을 설명 없이 섞지 않는 것이 좋다. [의견][^ref-1414][^ref-413]

### OPC UA for Robotics 의 서버 기능 묶음

OPC 40010-1(OPC UA for Robotics Part 1) 1.02판(2025-09-08)의 §11.2.2 는 서버 기능 묶음(Facet)을 기본(Base)·운전(MDS Operation)·자산관리 확장(AM Extended)·상태감시 확장(CM Extended) 넷으로 나누고, 표 124~127 에서 각 적합성 단위를 필수(M)와 선택(O)으로 구분한다. [사실][^ref-034] 그래서 연동 요구에는 'OPC UA 지원' 대신 OPC UA Robotics 판·서버 Facet·선택 단위·인증 범위를 적게 하고, 이 정보모델을 VDA 5050 주문 스키마와 일대일로 자동 변환할 수 있다고 보지 않는 것이 좋다. [의견][^ref-034] OPC 제품 인증은 재단이 인정한 시험소에서 받으며, 제조사는 인증 시험 전에 적합성 시험 도구로 미리 시험해 보도록 권고된다(6절). [사실][^ref-705][^ref-1423]

### MassRobotics AMR 상호운용 표준 스키마

MassRobotics 공식 JSON 스키마(커밋 f9357a4 기준)의 최상위 구조는 [신원 보고](../../glossary/identity-report.md)(identityReport)와 상태 보고(statusReport) 두 정의만 참조하고, 위치(location) 정의는 x·y·angle·planarDatum 네 필드를 모두 필수로 두며, 명령·주문·작업 메시지 정의는 없다(2026-10-11 확인). [사실][^ref-230] 따라서 이 보고 메시지(신원·상태) 교환만으로 작업 명령 호환성이나 좌표계 정합을 확보했다고 주장하지 않는 것이 맞다. [의견][^ref-230]

### 국내 표준

국가표준인증통합정보시스템(KSSN)에는 KS B 7321-2 '로봇 — 서비스 로봇 모듈용 정보 모델 — 제2부: 소프트웨어 모듈용 정보 모델'과, 이와 별도로 KS B ISO 22166-202 '로봇 — 서비스 로봇의 모듈화 — 제202부: 소프트웨어 모듈용 정보 모델'이 실려 있다(2026-10-11 확인). [사실][^ref-138][^ref-1424] 두 표준의 제정일·부합화 수준(IDT 여부)·고시번호와 서로의 대체 관계는 이번 열람에서 보이지 않아 미확인이다(oq-026).

### IDS 1.0 — 건물 정보 모델 데이터 교환 요구의 적합성 검사

buildingSMART 는 [정보 전달 명세](../../glossary/information-delivery-specification.md)(Information Delivery Specification, IDS)를 2024-06-01 승인된 공식 표준으로 소개하고, 데이터 요구를 기계가 읽을 수 있게 기술해 [IFC](../../glossary/ifc.md) 모델의 적합성을 자동으로 검사하게 한다고 설명하며, 1.0 이전 판은 공식 표준이 아니라고 밝힌다. [사실][^ref-1428] IDS 파일은 하나 이상의 명세(specification)로 이루어지고, 각 명세는 적용 대상(applicability)과 요구(requirements)를 가지며, 둘 다 엔터티·속성(attribute)·분류·속성 값(property)·재료·소속(partOf) 패싯으로 구성된다. [사실][^ref-1362] 받는 쪽은 IDS 와 IFC 를 함께 불러 검사해 불일치 보고를 얻는다. [사실][^ref-1362] 패싯 파라미터에는 단순 값 대신 열거·패턴·범위·길이의 복합 제한을 걸 수 있다. [사실][^ref-1365] 공식 저장소는 소프트웨어 구현의 IDS 읽기·검사 기능이 올바른지 확인하는 .ids·.ifc 쌍 250개 이상의 시험 파일 묶음도 둔다. [사실][^ref-1430]

이 영역(21. 상호운용 표준·적합성)에서는 IDS 1.0 을 IFC 데이터 교환 요구의 적합성 검사 수단으로만 짧게 두고, 검사 도구 자체도 공식 시험 파일 묶음으로 확인할 수 있다는 점을 적되 로봇–관제 메시지 적합성 시험과는 구별하는 것이 맞다. [의견][^ref-1428][^ref-1362][^ref-1430] 로봇 지도용 BIM 객체·속성 요구의 세부는 [14. 도면·BIM에서 지도 만들기](../../categories/space-and-map-model/maps-from-floor-plans-and-bim.md)와 [건축 도면 자동 인식](../../tracks/floorplan-recognition/index.md) 트랙에 두는 것이 맞다. [의견][^ref-1428] 이 소절은 건축 도면 자동 인식 트랙 실행 2026-10-09-26 의 반영 제안을 일부 반영한 것이다. 제안 가운데 기수(필수·선택·금지), 사용자 정의 속성 세트 명명 규칙, 뉴질랜드 OBOS 프록시 관례는 원문으로 확인하지 못해 싣지 않았다.
