# 22. 설비·건물 시스템 연동 — 관련 표준·프레임워크·오픈소스

## 1. 세 줄 요약

- 이 영역과 관련된 공개 규격은 오픈소스 메시지 정의와 로봇 탑승 안전 표준이 중심이다. [사실][^ref-286][^ref-314]
- 설비–로봇 연동 자체를 정한 국제 표준은 이번 조사에서 확인하지 못했다.
- 이 페이지는 [22. 설비·건물 시스템 연동](../../categories/integration/facility-and-building-system-integration.md) 페이지의 "관련 표준·프레임워크·오픈소스" 절이 분량 기준을 넘어 옮겨 온 것이다. 원 페이지의 검증을 거친 내용이며 새 주장은 없다.

## 2. 배경

[22. 설비·건물 시스템 연동](../../categories/integration/facility-and-building-system-integration.md) 페이지를 쓰는 과정에서 "관련 표준·프레임워크·오픈소스" 절의 분량이 세부영역 페이지 기준(4,000자)을 넘어, 내용을 줄이지 않고 이 주제 페이지로 분리했다.

## 3. 본문

이 영역과 관련된 공개 규격은 오픈소스 메시지 정의와 로봇 탑승 안전 표준이 중심이다. [사실][^ref-286][^ref-314] 설비–로봇 연동 자체를 정한 국제 표준은 이번 조사에서 확인하지 못했다.

| 이름 | 유형 | 이 영역과의 관계 | 출처 |
|---|---|---|---|
| Open-RMF 문·승강기 연동 문서 | 오픈소스 | 문·승강기 노드와 어댑터 구조를 설명한다. [사실] | [^ref-283][^ref-284] |
| Open-RMF 설비 메시지(rmf_lift_msgs·rmf_door_msgs) | 오픈소스 | 승강기 요청·상태, 문 모드 메시지를 정의한다. [사실] | [^ref-286][^ref-312][^ref-313] |
| Open-RMF 작업대 메시지(디스펜서·인제스터) | 오픈소스 | 예시 작업대의 요청·결과·상태 메시지다. [사실] | [^ref-023][^ref-047][^ref-049] |
| VDA 5050 3.0.0 | 표준 | 주변 설비 인터페이스는 범위 밖이고, 주변 시스템 통신은 관제 최소 기능이며, 해제·동작 구역을 둔다. [사실] | [^ref-031] |
| KS B 7317 이동 로봇의 엘리베이터 탑승을 위한 안전 요구사항 및 평가 방법 | 표준 | 로봇 자체의 탑승 안전 요구사항으로, 이 영역에는 제약 조건으로만 들어온다(원문 미열람). [사실] | [^ref-314][^ref-315] |
| 대한승강기협회 '엘리베이터와 로봇의 상호 연동을 위한 가이드라인' | 표준(단체표준) | 제정됐다고 보도됐으며 표준 번호·제정일·내용은 미확인이다. [사실] | [^ref-316] |

KS B 7317 과 관련해 국가기술표준원 보도자료는 로봇이 건물 안을 이동하고 엘리베이터에 타려면 속도 제어, 위험 상황에서의 보호 정지, 높낮이 차·틈새 극복, 추락·넘어짐 방지 기준이 필요하다고 설명한다. [사실][^ref-315] 이는 보도자료의 설명이며 표준 본문의 조항 구성은 미확인이다.

승강기 제조사 API 도 있다. KONE 은 청소·배송·보안용 자율 로봇을 자사 승강기와 연동하는 Service Robot API 를 엘리베이터 호출 API·설비 상태 API 와 함께 제공한다고 밝힌다. [추정] 벤더 주장[^ref-318] 현대엘리베이터는 2022년 3월 로봇이 엘리베이터를 호출해 탑승하는 '로봇 연동' 등을 제공하는 클라우드 기반 오픈 API 를 공개하고 추가 장비 없이 연동할 수 있다고 밝혔다(기사 출처, 회사 발표에 기댐). [추정] 벤더 주장[^ref-319] 현대엘리베이터는 오픈 API 참여 주체가 1년여 만에 60여 곳으로 늘었고 병원·호텔·은행 등에서 배송로봇이 자사 엘리베이터를 이용해 운행 중이라고 밝혔다(2023년 2월 기사 출처, 회사 발표에 기댐). [추정] 벤더 주장[^ref-320] 이들 API 의 메시지 구조·인증 방식은 미확인이다. 전체 목록은 [표준·프레임워크 목록](../../standards/index.md)에 있다.
