# 업무 연속성과 사람 개입

<!-- auto:page-status:start -->
> 페이지 상태: published · 신뢰도: medium · 페이지 버전: 1 · 마지막 갱신: 2026-10-12 · 마지막 실행: 없음
<!-- auto:page-status:end -->

로봇이 멈췄을 때 업무가 멈추면 안 된다. 그렇다고 다른 로봇이나 사람을 바로 보내면 같은 일을 두 번 하거나, 반쯤 옮긴 화물이 어디 있는지 모르게 된다. 이 페이지는 정지 확인부터 업무 재개까지 거쳐야 할 관문과, 사람 개입을 성과 지표에서 감추지 않고 기록하는 방법을 정리한다.

## 1. 현장 문제

발표 관찰: 현장에서 로봇이 멈추거나 실패하면 사람이 다가가 조치하거나 원격으로 조작·리셋하는 장면이 소개됐다. 시연 영상의 어느 구간이 자율 수행이고 어느 구간이 원격 조작인지는 발표 자료로 확인할 수 없었다.

[추정] 벤더 주장: 휴머노이드 제품 발표 자료는 자율 모드, 원격 조작, 태블릿 조종의 세 가지 제어 방식을 구분한다.[^ref-1575] 같은 로봇도 제어 방식에 따라 성과의 의미가 달라진다는 뜻이다.

## 2. 근거·적용 조건

이 페이지의 관문과 기록 항목에는 직접 대응하는 공개 표준을 찾지 못했다. 기존 위키의 명령 신뢰성·사람 협업·예외 복구·배포 연구(7절)를 현장 인계 관점으로 좁힌 제안이다. 통신 단절 뒤 로봇이 확정된 노드까지 계속 움직일 수 있다는 규격상 의미[^ref-031]는 "통신이 끊겼다 = 멈췄다"로 볼 수 없는 이유다.

## 3. ROP 판단

[의견] 정지에서 재개까지 여섯 관문을 차례로 통과해야 한다.

| 관문 | 확인할 증거와 결정 | 통과 조건 |
|---|---|---|
| 정지·격리 | 물리적 정지, 적재 상태, 설비 점유 확인. 통신 단절만으로 정지를 확정하지 않는다 | 확인하지 못한 공간·화물은 점유 또는 확인 대기로 처리 |
| 원인 판단 | 로봇·환경·통신·설비·관제·업무 오류를 나눈다. 원인 가설과 확정을 구별 | 지금 적용할 제한과 조사 책임자 지정 |
| 사람·다른 로봇 투입 | 같은 작업을 두 주체가 소유하지 않게 한다. 대체 주체의 능력·접근·적재·도구 확인 | 대체 주체의 수락과 원래 수행자의 실행 차단 확인 |
| 인계 | 물체·작업·검사 상태, 이동 전후 위치, 수량·식별, 책임 수신 | 보낸 쪽과 받은 쪽의 증거가 일치하거나 사람이 확인 |
| 품질 확인 | 점검 누락, 손상, 검체·상품·공정 품질, 재고 대조 | 업무 소유자가 통과·재작업·폐기를 판단 |
| 재개 | 원인 처리, 회귀 검증, 임시 제한, 최신 구성 승인 | 재개 승인과 추적 가능한 새 실행 기록 |

[의견] 개입은 종류별로 따로 기록한다. 자율 수행, 원격 조작, 원격 리셋, 현장 물리 개입, 수동 대체는 서로 다른 개입 유형이다. 리셋 뒤 로봇이 스스로 끝낸 작업도 "무개입 성공"으로 세지 않는다. 개입을 기다린 시간, 처리 시간, 재검사 시간은 실행 시간과 함께 리드타임에 넣는다([리드타임·성숙도와 비용](lead-time-and-maturity.md)).

[의견] **로봇 고장 복구**와 **관제 소프트웨어 무중단 배포**는 서로 다른 문제다. 고장 복구의 관문은 물리 안전·화물·재시동과 정비·현장 품질이다. 소프트웨어 순차 배포의 관문은 세션과 명령 소유권 이관, 작업 상태 지속성, 호환되는 데이터베이스와 이벤트, 신구 버전의 중복 실행 방지와 롤백이다. 한쪽의 성공을 다른 쪽이 무중단이라는 증명으로 쓰지 않는다.

## 4. 제조사·설비·운영자 역할

[의견] 업무 완료는 업무 소유자가 승인한다. ROP는 화물·점검의 상태와 인계 증거를 모아 보여 주지만, 품질 판정(통과·재작업·폐기)은 업무 소유자의 몫이다. 제조사는 원격 조작·리셋 기능의 범위와 기록 방법을, 현장 운영자는 누가 어떤 권한으로 개입했는지를 남긴다. 설비 담당은 사람이 수동으로 설비를 움직인 뒤 자동 운용으로 돌아가는 절차를 책임진다.

## 5. 대응·판단 기준

- [의견] 응답이 사라졌을 때 실물 이동을 확인하기 전에는 작업을 다른 로봇에 다시 배정하지 않는다.
- [의견] 개입 기록에는 개입 유형, 시작·종료 시각, 개입한 사람의 역할(개인 식별 정보 대신), 원격인지 현장인지, 개입 전후 로봇·화물 상태, 승인자를 넣는다.
- [의견] 재개는 원래 실행을 이어 붙이지 않고 새 실행 기록으로 남긴다. 원래 실행과 새 실행은 같은 업무 id로 잇는다.
- [의견] 소프트웨어 배포 중에는 배포 전후로 같은 명령이 두 번 나가지 않았는지, 진행 중이던 작업 상태가 사라지지 않았는지를 실물 작업 상태와 대조해 확인한다.

## 6. 검증·한계

- 관문과 기록 항목은 제안이다. 실제 현장 운영 로그로 검증하지 않았다.
- 발표 시연 영상의 실제 제어 방식·편집 구간·성공률은 확인하지 못했다. 관찰 기록 없이 자율 성공으로 세지 않는다.
- 제품이 세 가지 제어 방식을 지원한다는 것은 제조사 설명이다. 각 방식의 현장 성능은 확인하지 않았다.
