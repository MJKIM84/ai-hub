# 발표 구성과 예상 질문

<!-- auto:page-status:start -->
> 페이지 상태: published · 신뢰도: medium · 페이지 버전: 1 · 마지막 갱신: 2026-10-12 · 마지막 실행: 없음
<!-- auto:page-status:end -->

세 과제(① 서비스·사업, ② ROP·연동, ③ 구축·운영) 가운데 둘을 골라 발표할 때의 조합, 15분 발표의 장 구성, 받을 만한 질문 10개와 답하는 데 필요한 근거를 정리한다. 모두 [의견]이며 발표 문구의 완성본이 아니라 근거 배치안이다. 자료 번호 S01~S18은 [핵심 학습 자료](core-materials.md)다.

## 두 항목 조합

| 조합 | 설득력 있는 지점 | 빠지기 쉬운 것 | 권장 대상 |
|---|---|---|---|
| **① 서비스·사업 + ③ 구축·운영** | 고객 가치 → 실제 운영 조건 → 비용·인수로 이어진다 | ROP가 단순한 "관제 화면"으로 보일 수 있다. 책임 경계·시퀀스 한 장을 보충 | **기본 추천.** 서비스·사업·제품 PM |
| ② 아키텍처 + ③ 구축·운영 | 분산 연동의 실패와 현장 검증을 구체적으로 잇는다 | 사용자 가치·경제성이 빠질 수 있다. 완료 정의·비용 표를 보충 | 플랫폼·솔루션·기술 PM |
| ① 서비스·사업 + ② 아키텍처 | 요청·상태·사용자 경험을 시스템 계약으로 잇는다 | 시설 가능성과 인수·유지보수 부담을 놓치기 쉽다 | 서비스 플랫폼 PM, 구축 인프라가 이미 있는 경우 |

**주장할 제안의 범위:** 평탄한 구역의 배송·안내를 4휠 중심으로 검토하고, 계단·비정형 접근의 점검 공백이 확인되는 경우 4족을 추가 비교한다. 한 종류나 사람·고정 센서만으로 충분하면 이종 로봇을 도입하지 않는다. 근거는 제품의 조건부 기능, 빌딩 통합 사례, 점검 운영 사례이며, ROI와 안전성은 시범으로 검증할 가설이다.

## 15분·9장 구성 예시

| 장·시간 | 설명할 질문 | 보여 줄 근거·산출물 |
|---|---|---|
| 1 · 1분 | 누구의 어떤 업무를 바꾸는가 | 가정한 빌딩, 지불자, 기존 업무 기준선, 미확인 항목 |
| 2 · 2분 | 왜 이 서비스·기종 조합인가 | 4휠·4족 적합성, 단일 기종·사람 대안, S01~S03 |
| 3 · 2분 | 무엇을 서비스 완료로 볼까 | 배송 인계, 점검 유효 데이터, 안내 도착·직원 인계, S05·S06·S17 |
| 4 · 1.5분 | 누가 비용을 내고 어떻게 효과를 보나 | TCO와 시나리오별 ROI. 가상 수치와 실제 견적의 구분 |
| 5 · 2분 | ROP와 제조사·시설은 무엇을 결정하나 | 구성도, 책임 경계, S07~S09 |
| 6 · 2분 | 승강기 단절·수령자 부재 때 어떻게 끝내나 | 배송 시퀀스, 취소·상태·물품 인계 원장, S04·S10 |
| 7 · 2분 | 우리 현장에서 어떻게 입증하나 | 조사표, RACI, 우선 시험 8개(T03·T04·T05·T07·T08·T09·T11·T12), 인수 목표, S11~S16 |
| 8 · 1.5분 | 시범 뒤 확대·중단을 어떻게 결정하나 | 성공률, 개입 시간, 유효 커버리지, 실제 비용, 잔여 위험 |
| 9 · 1분 | 지금 승인받을 것은 무엇인가 | 제품 구매 확정이 아니라 현장 조사·API·견적 확보·시범 범위 |

## 예상 질문 10개

| 질문 | 답변의 판단 구조 | 필요한 근거 |
|---|---|---|
| 1. 왜 4휠과 4족을 둘 다 쓰나? | 접근할 수 없는 중요 점검점이 있을 때의 추가 가치와 복잡도를 비교한다. 없으면 한 종류 | S01~S03, 실제 경로·점검점, 시설 개선·사람 대안의 비용 |
| 2. Spot이면 모든 계단과 문을 해결하나? | 계단 형상·적재별로 승인하고, 본체와 Arm·문 조작의 검증을 분리한다 | S02·S03, 현장 계단·문 시험, 구매품 매뉴얼 |
| 3. 로봇이 목적지에 왔으면 성공 아닌가? | 배송 수령, 점검 데이터 품질, 안내 일행 도착을 따로 확인한다 | S04·S06·S18, 인계·측정·동행 증거 |
| 4. Open-RMF를 쓰면 ROP 개발은 끝나나? | 어댑터의 제어 수준, 시설, 서비스, 권한, 운영 계약이 남는다 | S07·S08, 제조사 API 가능표와 작업 책임표 |
| 5. VDA 5050을 지원하면 바로 섞어 쓸 수 있나? | 판·선택 기능·오류·취소·지도·행동의 양방향 시험이 필요하다 | S09, 제조사 지원 문서, 적합성 시험 결과 |
| 6. 통신이 끊기면 정지시키면 되지 않나? | 외부망과 현장 무선, 기체와 설비, 4족의 자세와 화물 상태를 나눈다. 정지 요청과 정지 확인을 구별한다 | S04·S10, 단절 시험, 시설 점유·재연결 기록 |
| 7. 사람 대신 로봇을 쓰면 얼마나 절약하나? | 수요, 남는 인력 시간, 개입, 전체 비용, 현금화 비율을 공개한다 | 기준선, 실제 견적·계약, [사업 모델과 경제성](business-model-and-roi.md)의 계산 모델 |
| 8. 사고·파손·분실 책임은 누구에게 있나? | 법적 주체, 계약, 원인, 실물 보관 이력으로 판단한다. RACI만으로 면책되지 않는다 | 운영·운송·유지보수 계약, 보험, 인계 원장, [현장 구축과 인수시험](deployment-and-acceptance.md)의 법 적용표 |
| 9. 카메라 영상과 방문객 인증은 어떻게 관리하나? | 목적·구역·수집 근거·표시·거부·위탁·접근·보관·삭제를 분리한다 | S14·S15, 개인정보 보호법 제26·29조, 고객 개인정보 검토와 데이터 흐름 |
| 10. LLM을 넣으면 더 자율적인가? | 자연어 편의와 실행 허용·제어 능력은 별개다. 선택 기능으로 평가한다 | [ROP 책임 경계와 연동 계약](architecture-and-contracts.md)의 실행 게이트·권한 시험, 사용자 과업 성공·비용 비교 |

## 추가 확인 과제

공개 자료로 닫을 수 없는 질문이다. 미확인은 "기능 없음"이나 "법적으로 불가"라는 뜻이 아니다.

| 우선순위 | 확인할 정보 | 확인 주체 | 닫는 증거 |
|---|---|---|---|
| P0 | 현장 도면, 피크 수요, 기존 업무 시간 | 고객·시설 운영 | 실측·관찰, 승인된 서비스 구역·물량 |
| P0 | 실제 기체·센서·적재·펌웨어 구성과 상충 사양 | 제조사·공급사 | 구성 번호가 붙은 견적·매뉴얼·제한·국내 지원표 |
| P0 | API 권한·취소·상태·제어 소유권·판 지원 | 제조사·ROP | 샌드박스·실기 문서, 샘플, 인터페이스 시험 증거 |
| P0 | 승강기·문·출입의 연결 허가와 가격 | 설비 업체·관리주체 | API·제어반, 변경 범위, 승인·검사 검토, 계약 |
| P0 | 안전·인증, 배터리, 무선, 전기 적용 | 제조사·안전/설비 전문가 | 해당 구성의 선언·시험·위험 평가·법 적용 검토 |
| P0 | 영상 목적, 법적 주체, 보관·위탁, 국외 이전 | 고객 개인정보/보안·법무 | 데이터 흐름, 처리 근거, 정책, 계약, 권리 대응 |
| P0 | 완료·인계·상하차·분실/손상·대체 업무 | 고객 운영·계약/보험 담당 | 인계 원장, 약관·SLA, 보험과 역할 서명 |
| P1 | 소음, 접근성, 사람 수용성 | 고객·사용자 조사 담당 | 같은 조건의 계측·관찰·설문·직원 인계 시험 |
| P1 | 성능, 배터리, 커버리지, 회전 여유 | 제조사·현장 검증팀 | 하중·경로·조명·무선·기체 판별 시험 결과 |
| P1 | TCO, 현금화, 운영 인력, 지원 SLA | 공급사·고객 재무/운영 | 항목별 견적, 기준선·운영 시간·시나리오 민감도 |
