# 현장 구축과 인수시험

<!-- auto:page-status:start -->
> 페이지 상태: published · 신뢰도: medium · 페이지 버전: 1 · 마지막 갱신: 2026-10-12 · 마지막 실행: 없음
<!-- auto:page-status:end -->

PM이 관리할 구축 단계, 현장 조사표, 역할 분담(RACI), 수치 기준의 출처 구분, 시험 계층과 핵심 시험 14개, 장애 대응, 국내 법령의 적용 범위를 정리한다. 조사용 가정은 국내 다층 업무빌딩이며 실제 현장 조사·운전·시뮬레이션의 결과가 아니다. 단계·RACI·시험·합격 목표·복구 절차는 모두 **[의견]**이고, 기체·설비 담당자의 안전 설계와 고객 승인을 받아 구체화한다. 자료 번호는 [핵심 학습 자료](core-materials.md)의 카드다.

## PM이 관리할 구축 8단계

| 단계 | 필수 산출물 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1 현장 조사 | 도면, 경로·점검점, 시설·통신, 사람 동선, 현행 업무 기준선, 제약 목록 | 현장 소유자와 실측 결과 확인. 조사가 끝나지 않은 구역은 범위에서 분리 |
| 2 요구와 수용 기준 합의 | 세 서비스의 완료 정의, 물품·점검 조건, SLA, 시험 범위, 책임·비용 | 고객·시설·기체·플랫폼 담당자가 같은 분모와 실패 정의에 합의 |
| 3 설계 | 기체·센서·함체 구성, 책임 경계, 망·시설 API, 지도·설정, 위험 평가 | 연동 가능성, 안전·법·개인정보 검토, 비용·공정 승인 |
| 4 설치·연동 | 승인된 공사·설비 설정, 등록·인증서, 지도 정합, 기체·설비 버전표 | 개별 기체·설비 기능 확인과 되돌리기 계획 확보 |
| 5 시험 | 단위·인터페이스·E2E·장애 시험 결과, 결함·회귀 기록 | 중대한 미해결 위험, 완료 위조, 중복 물리 실행 같은 출시 차단 결함 해소 |
| 6 시범 운영 | 제한 구역·시간대·적재·이용자 범위, 직원 대체 운영, KPI 기준선 비교 | 합의한 표본·조건으로 성능·개입·비용·불편 확인. 확대 또는 축소 판단 |
| 7 인수 | 요구별 증거 대조표, 현장 인수시험, 잔여 결함·조건부 범위 승인 | 고객 인수권자가 증거와 잔여 제한에 서명. 시연 성공으로 대체 불가 |
| 8 운영 이관 | 매뉴얼, 교육, 당직·출동, 부품, 권한, 백업·복구, SLA, 변경 관리 | 현장 담당자가 장애·인계·복구 훈련을 하고 운영 책임을 수락 |

제품 매뉴얼의 사용 조건과 계약 조건을 인수시험으로 옮기되, 문서 적합성·인터페이스 적합성·현장 서비스 성공을 따로 증거로 관리한다. 반복과 조건 통제의 방법은 NIST 시험 방법,[^ref-1580] 제조사 실행 피드백은 Spot SDK 문서를 참고한다.[^ref-1579]

## 현장 조사표와 대안 선택

| 조사 항목 | 측정·관찰 방법 | 담당 | 설계·비용 결정 |
|---|---|---|---|
| 통로·문·회전 공간 | 최소 유효 폭, 문 열림 궤적, 적재 외곽, 실제 회전·대기 위치를 도면과 실측 | 시설 + 로봇 제조사 | 속도·회전 조정으로 부족하면 경로 분리·시간대 변경·시설 개선을 비교 |
| 문턱·경사·계단 | 단차, 경사·길이, 계단 디딤·챌면·참, 상·하행과 적재 조건 | 제조사 + 시설, 안전 담당 검토 | 승강기 우회, 경사로, 사람 대체, 4족 후보를 비교. 보행 가능과 안전 승인을 구별 |
| 바닥 마찰·오염 | 재질·줄눈·카펫·청소 시간·물기와 기름 발생 구역, 승인된 시험으로 미끄럼·정지 관찰 | 시설 청소·보전 + 제조사 | 오염 제거·관리 절차가 먼저. 파라미터 변경만으로 해결했다고 보지 않는다 |
| 반사·투명체·조명 | 유리·금속, 역광, 그림자, 야간 조도, 특징 부족 구간을 센서 위치에서 기록 | 제조사 + 시설 | 표식·경로·조명·센서/알고리즘 변경의 비용과 재시험 범위 비교 |
| 센서 시야·점검 품질 | 적재가 시야를 가리는지, 측정 거리·각도·온도·방사율·교정·가림 확인 | 센서 담당 + 보전·품질 | 마운트 변경, 점검점 재설계, 고정 센서와 비교[^ref-1589] |
| 승강기·자동문·출입 | 모델, 제어반, API·접점, 라이선스, 권한, 층 대응, 수동·화재 모드, 장애 연락망 | 설비 업체 + 시설 + ROP | 지원이 없으면 통합 개발·공사·계약 또는 서비스 범위 축소[^ref-284] |
| 무선·로밍·망 접근 | 로비·복도·계단·승강기 안의 왕복 이동. 신호 세기만이 아니라 유실·지연·로밍과 재연결·시각 오차 | 고객 IT·망 담당 + ROP + 제조사 | AP·현장망 개선, 엣지 배치, 통신 모듈, 보안 접근 비용 |
| 충전·대기·상하차 | 전원, 열·환기, 시설 조건, 차량·보행 피난 동선, 충전 접근, 고장 로봇 회수 공간 | 시설 + 제조사 + 운영 | 전기 공사, 면적 기회비용, 추가 충전소·예비 기체 |
| 사람·접근성·소음 | 피크·야간 관찰, 휠체어·보행 보조기·짐·방문객, 직원 인터뷰, 조건을 정한 소음 측정 | 고객 운영 + 접근성·안전 담당 | 운행 시간, 속도, 안내 UX, 직원 인계, 서비스 범위 결정 |
| 기존 업무·비용 | 요청부터 인계·검사까지 시간 관찰, 재작업·개입·수요·인력 투입 기록 | 고객 PM + 현장 운영 | 로봇 도입 전 기준선과 경제성 분모 확보 |

**현장 차이:** 업무빌딩은 방문객 권한, 피크 승강기, 공용 복도, 시선·소음이 핵심 가정이다. 공장은 교대, 공정 안전, 설비 점검 품질, 오염, 공정 정지 비용이 더해진다. 호텔은 야간 소음, 객실 사생활, 수령자 부재를 별도 요구로 검토한다. 이는 현장 가설이며 BMW의 공장 사례가 빌딩·호텔의 성공을 입증하지는 않는다.[^ref-1600] 조건별 측정 방법과 설정·경로·시설 개선의 선택 기준은 [현장 적용·운영 검증 — 로봇 친화 현장 조건](../field-readiness-rop/robot-friendly-sites.md)이 더 자세하다.

## RACI 초기안

R 실행, A 최종 승인·책임 창구, C 협의, I 통보. 각 행의 A는 하나다. **사업 계약의 업무 분담 예시이며 법정 책임을 이전하는 표가 아니다.** 고객의 IT·보안·개인정보·안전 담당자는 관련 행의 고객사 C/R에 포함한다. 제조사가 통합 사업자 역할을 맡으면 계약에 맞게 조정한다.

| 업무 | 로봇 제조사 | ROP 개발사 | 시설 운영사 | 설비 업체 | 고객사 |
|---|---|---|---|---|---|
| 서비스 범위·완료·예산·SLA | C | C | R | C | A |
| 현장 조사와 출입·피난·운영 시간 확인 | C | R | A/R | C | C |
| 기체·페이로드 운용 한계와 정비 기준 | A/R | C | C | I | C |
| 작업 상태·중복·어댑터·로그 연동 | C | A/R | C | C | C |
| 승강기·문 제어기 변경 설계·시공·검증 | I | C | A | R | C |
| 시설 사용·정비/화재 모드·복귀 허가 | C | C | A/R | R | I |
| 고객 망·보안·개인정보 처리 승인 | C | R | C | C | A/R |
| 종합 위험 평가·서비스 운영 허용 | R | R | R | C | A |
| 통합 시험 수행·결함 분류 | R | A/R | R | R | C |
| 현장 인수·잔여 조건 승인 | C | R | R | C | A |
| 일상 관제·물품 인계·현장 대응 | C | C | A/R | C | I |
| 기체 수리·기체 펌웨어 수정 | A/R | C | C | I | I |
| 플랫폼 SW 배포·롤백 | C | A/R | C | C | I |
| 사고·분실의 고객 대응과 계약 조정 | C | C | R | C | A |

RACI와 별개로 고객은 위험 평가의 법적 사업주, 시설 관리주체, 개인정보처리자, 실제 운송·보관 책임자를 식별해야 한다. 이름 없는 "공동 책임"만 두면 장애가 생겼을 때 결정권이 비게 된다.

## 수치 기준의 출처와 합의 구별

| 기준 종류 | 사용 원칙 | 예시 |
|---|---|---|
| 제조사 제한 V | 정확한 구성·판·적재·환경에서 적용. 단순 최고 성능이 아니라 운용 한계 확인 | Spot 합산 페이로드 14 kg, Arm 포함.[^ref-1597] 구매품 확인 필요 |
| 표준·법 의무 N | 적용 범위·판·전문·제품 선언을 전문 담당자가 확인 | ISO 13482·3691-4는 공개 초록만 읽었으므로 정지 거리·충돌력 수치를 제시할 수 없다[^ref-1602][^ref-470] |
| 고객 성과 목표 T | 기준선·업무 가치·시험 결과를 보고 고객과 합의 | 배송 p95 리드타임, 유효 점검 커버리지, 안내 인계율, 개입 시간 |
| 안전 설계 한계 E | 기체·하중·바닥·감지와 제동 지연·설비 특성으로 엔지니어가 결정 | 시험용 최대 속도, 접근 거리, 정지 외곽. PM이 임의 숫자로 채우지 않는다 |

**가상 성과 목표 예시(T):** 제한 구역·승인된 적재·평일 업무 시간에 배송 200건 이상을 관찰하고, 서비스 성공률 95% 이상·p95 리드타임 15분 이하를 검토하는 식으로 협상한다. **검증된 성능도 법정 합격값도 아니다.** 두 목표를 만족해도 안전 적합성을 증명하지 않는다. 표본은 층·피크/비피크·문/승강기·기체 구성별로 나눠 분모를 공개하며, 실패·중단·사람 대체를 빼서 숫자를 부풀리지 않는다.

## 시험 계층과 공통 증거

1. **단위 기능:** 기체 주행·정지·충전, 센서 획득, 적재함, 시설 제어·관측을 각각 확인.
2. **인터페이스:** id, 좌표, 시간, 판, 중복, 순서 역전, 취소, 오류, 권한, 재연결 확인.
3. **서비스 E2E:** 요청부터 실제 인계·유효 측정·방문객 도착까지 연결.
4. **장애 주입:** 네트워크·상태·명령과 응답·센서 실패를 통제된 조건에서 주입. 원인의 물리 재현과 분리.
5. **현장 인수:** 실제 층·설비·운영 시간·이용자 특성·부하에서 합의한 업무 기준을 고객과 확인.

공통 시험 기록: 시험 id / 요구 id / 위험 검토 / 현장·경로·층 / 기체·페이로드·적재 / 펌웨어·SDK·ROP·어댑터·지도·설정 판 / 환경·망 조건 / 절차 / 예상 결과와 수치의 V·N·T·E 구분 / 관측값 / 합격 여부 / 로그·영상·측정 증거 / 담당·승인 / 결함·재시험. 개인정보가 담긴 증거는 수집 근거·접근권·보관 기간을 정한다.

## 핵심 시험 14개와 복구

모든 행은 [의견]이다. E 값이 정해지지 않았거나 위험 통제가 안 된 시험은 실행을 승인하지 않는다. 사람 돌발 진입 시험은 먼저 대체 표적·통제 공간과 전문 담당자의 절차로 준비한다.

| 시험·계층 | 조건 | 관측값 | 합격 기준 제안 | 복구 절차 | 증거 |
|---|---|---|---|---|---|
| T01 주행·정지·회전 / 단위 | 승인 하중·바닥·속도·최소 통로, 양방향 | 외곽, 미끄러짐, 정지 거리, 측위, 안전 상태 | V·E 범위 안, 허용 구역 침범 없음. 숫자는 기체 담당 확정 | 운행 차단 → 하중·경로·바닥 수정 → 같은 조건 재시험 | 실측 도면, 기체 로그, 통제 영상 |
| T02 센서 측정 / 단위 | 같은 대상·거리·각도·교정·환경, 알려진 기준값 | 오차, 반복성, 가림, 품질 표시 | 합의된 측정 오차 T·E 충족. 무효 측정은 invalid | 재초점·재측정 → 센서 확인 → 사람 측정 | 교정 성적, 기준기 비교, 원본과 메타데이터 |

| T04 취소·완료 경합 / 인터페이스 | 배송 출발 뒤, 인계 직전, 인계 직후 취소 | 취소 요청, 물리 상태, 화물 소유, 최종 상태 | 서로 모순되는 완료·취소 이중 확정 없음. 화물 책임 공백 없음 | 회수·반송·분쟁 하위 작업, 승인된 결과 확정 | 상태 이력, 인계 영수증, 감사 |
| T05 다중 로봇 경쟁 / E2E·장애 | 승강기·좁은 통로·충전소를 두 기체가 동시 요청 | 예약, 실제 점유, 대기 시간, 기아, 정체 | 동시 위험 진입 없음, 합의한 대기·처리량 T. 만료만으로 점유 해제 안 됨 | 대기 → 우선권·우회 → 담당자 해소 → 소유권 재확인 | 세션·점유·교통·작업 타임라인 |

| T07 네트워크 단절 / 장애 | 외부망 단절과 로봇 무선 단절·로밍을 따로, 수행 도중 | 상태 나이, 로봇 행동, 시설 점유, 재전송, 시계 오차 | 계약된 로컬 안전 동작, stale 표시, 중복·허위 완료 없음 | 연결 복구 → 로봇·설비·화물 대조 → 소유권 재획득 → 재개 | 단절 시점, 망 계측, 기체·ROP 로그 |
| T08 승강기 불가 / 장애·인수 | 정비·수동·화재 모드, 층·문 관측 불일치, 내부에서 단절 | 진입 차단, 세션, 점유, 작업 상태, 알림 | 불명확한 조건에서 진입 금지, 현장 설비 우선권 유지 | 시설 담당 확인 → 우회·사람 배송 → 현장 복귀 허가 | 설비 이벤트, 층·문 상태, 현장 확인 |

| T10 배터리 부족 / 단위·E2E | 하중·센서·대기와 승강기 지연 포함, 오래된 잔량도 시험 | 잔량, 소모, 예약, 귀환 가능성, 온도 | 제조사 보호 한계 V 준수, 합의한 예비 잔량 T·E와 인계·충전 계획 | 신규 배정 제한 → 확인된 인계 → 충전·교환·회수 | 배터리 로그, 작업·충전 일정 |
| T11 측정 데이터 실패 / E2E | 영상 가림, 열화상 오보정, 타임아웃, 빈 데이터 | 도착·획득·검증·저장 상태를 각각 관찰 | 도착 성공이어도 invalid 측정은 점검 완료에 넣지 않음 | 제한 재측정 → 사람 확인 → 미확인 보고 | 원본, 품질 표시, 재측정, 검토자 |
| T12 물품 인계 실패 / E2E·인수 | 부재, 잘못된 인증, 잠금 불일치, 인출 미확인, 손상 신고 | 문 개폐, 인출, 인증, 화물 보관자, 알림 | 권한 없는 개방·허위 완료 없음. 실패·반송 이력 유지 | 직원 회수 → 검수 → 재배송·반송 → 분쟁 처리 | 최소 인계 증거, 함체 로그, 서명·토큰 |
| T13 안내 동행 이탈 / E2E·인수 | 일행이 멈춤·방향 전환, 다른 사람 접근, 언어·접근성 요구 | 동행 유지, 불편, 정지 위치, 직원 인계 | 일행 미도착을 성공 처리하지 않음. 합의한 UX·T 준수 | 허용 대기 → 재확인 → 직원 안내·중지 | 동의와 적법한 관찰, 설문, 개입 기록[^ref-1606] |
| T14 버전·권한·재시작 / 인터페이스·장애 | 다른 지도 판, 만료 토큰, ROP 재시작, 늦은 이전 세션 명령 | 실행 거절, 소유권, 작업 복원, 설비 상태 | 비호환·무권한 실행 차단, 현재 작업의 일관성 유지 | 승인 판 복원 → 접근 재발급 → 상태 재조정 뒤 재개 | 설정 해시, 감사, 재시작 전후 원장 |

[의견] 시간이 제한되면 중복·취소·자원 경쟁·단절·승강기·위치·측정·인계를 다루는 T03·T04·T05·T07·T08·T09·T11·T12를 먼저 한다. 각 조건은 정상·경계·실패와 반복 수를 명시한다. 서비스 성공률은 표본 수·기간·예외 포함 여부와 함께 보고한다. 서로 다른 하중·지도·기체·펌웨어의 결과를 한 평균으로 합쳐 제한을 숨기지 않는다.

**사건 주입과 실제 원인의 재현은 다르다.** 통신 단절 이벤트를 넣어 ROP의 상태·복구 논리를 시험한 것은 실제 빌딩의 전파 음영·로밍 성능을 입증한 것이 아니다. 위치 상실 상태를 넣어 배정 차단을 확인한 것은 유리·그림자가 그 센서에 위치 상실을 일으키는 인과를 재현한 것이 아니다. 낮은 마찰값을 넣은 동역학 모델은 바닥·타이어·발·오염·하중에 맞는 실측 보정이 필요하다. 승강기 out-of-service 메시지를 주입한 것은 실제 제어기의 모드 전환·인터록·층 정확도 시험을 대신하지 않는다. 증거 수준의 구분은 [현장 적용·운영 검증 — 시뮬레이션 검증 범위](../field-readiness-rop/simulation-validation.md)에 있다. 이 조사에서는 어떤 시뮬레이터도 실행하지 않았다.

## 장애 대응과 업무 연속성

| 단계 | 담당과 수행 | 완료 증거 |
|---|---|---|
| 탐지 | ROP·기체·설비·현장 신고를 연결. 발생·관측·수신 시각 구분 | 상태·센서·오류·작업 id가 연결된 사건 |
| 분류 | 관제가 안전 위험, 기체, 망, 설비, 데이터 품질, 인계, 보안으로 분류 | 우선순위, 영향 구역, 화물·사람 영향, 불확실한 점 |
| 안전 상태 유지 | 기체·설비의 검증된 로컬 기능과 현장 통제로 위험 억제 | 실제 위치·정지 자세·화물·시설 점유 확인. 명령 전송만으로 대체 불가 |
| 담당자 통보 | 현장 운영과 제조사·ROP·설비 업체에 필요한 증거만 전달 | 수신 확인, 사건 소유자, 대응 기한, 대체 업무 담당 |
| 원격·현장 조치 | 명령 소유권 확보 뒤 승인된 조치. 필요하면 사람·다른 로봇 대체 | 조작자, 모드, 조치, 실제 화물·데이터 인계 기록 |
| 재개 승인 | 복구 조건, 현재 구성, 위치, 시설, 업무 품질을 점검하고 권한자가 승인 | 복귀 조건 점검, 승인자, 재개 시각 |
| 원인 분석·재발 방지 | 재현, 로그, 개선, 회귀, 운영 제한 갱신 | 원인 확신 수준, 해결책, 회귀 증거, 롤백 가능성 |

**원격 조작은 자율 성공이 아니다.** 원격 조작, 리셋, 현장 이동, 물품 회수, 수동 센서 측정을 유형과 분 단위로 기록한다. [추정] 벤더 주장: Spot SDK 5.2의 Keepalive는 halt와 motors-off를 구분하므로, 전원 차단·정지의 의미는 기체 판별로 확인한다.[^ref-1383] 모든 4족에 바퀴 로봇과 같은 "즉시 전원 차단" 절차를 적용하지 않는다.

**로봇 고장 복구**는 기체·센서·위치·물품·공간의 물리 상태 복원이고, **관제 SW 배포·복구**는 프로세스·DB·명령 소유권·스키마·어댑터 연결의 복원이다. 둘을 분리해서 시험한다. 서버 프로세스가 재기동됐다고 운송을 재개하거나, 기체를 수리했다고 지도·설정 회귀를 생략하지 않는다. 정지에서 재개까지의 관문과 개입 유형의 기록은 [현장 적용·운영 검증 — 업무 연속성과 사람 개입](../field-readiness-rop/continuity-and-human-intervention.md), 제조사에 보낼 재현 패키지의 필드는 [제조사 피드백 패키지](../field-readiness-rop/manufacturer-feedback.md)에 있다.

## 대한민국 적용 범위와 전문 검토

**법령 사실과 적용 제안을 분리한다.** 법령 화면의 시행일은 읽은 판의 표시이며, 개별 건물·사업·제품에 대한 적용 판정은 하지 않았다.

| 공식 근거 | 확인한 범위 | 이 과제의 적용과 남은 검토 [의견] |
|---|---|---|
| 산업안전보건법 제36조 | [사실] 사업주의 유해·위험 요인 평가·개선, 근로자 참여·고지·기록에 관한 규정[^ref-1607] | 고객의 사업주·도급 구조와 실제 근로자 업무에 맞춰 안전 담당이 검토한다. 방문객 전체의 안전 검토를 이 법 하나로 대체하지 않는다 |
| 개인정보 보호법 제25조의2 | [사실] 공개된 장소에서 업무 목적의 이동형 개인영상 촬영 제한·허용 요건·고지[^ref-1603] | 공개 로비와 제한 사무 구역을 구분하고 촬영 목적·거부·사생활 구역 처리를 정한다. 얼굴 인증·마케팅·학습 전용은 별도 검토 |
| 개인정보 보호법 제26조 | [사실] 처리 업무 위탁의 문서·공개·수탁자 교육과 감독. 제8항은 수탁자에게 제25조의2와 제29조를 준용한다[^ref-1608] | ROP 클라우드·관제·유지보수의 영상 접근이 위탁인지 별도 제공인지 검토하고 계약·권한에 반영 |
| 개인정보 보호법 제29조 | [사실] 기술적·관리적·물리적 안전조치 의무[^ref-1609] | 원본 영상 접근 제한, 변경·열람 기록, 보관·삭제를 설계. 구체 고시·국외 이전·보관 기간은 개인정보·보안 담당 후속 확인 |
| 소방시설법 제16조, 승강기법 제32조 | [사실] 피난시설 방해 제한, 승강기 안전검사와 수시검사 사유[^ref-1604][^ref-1605] | 충전·대기·고장 로봇이 피난 동선을 막지 않게 설계. 제어 변경이 검사 대상인지는 업체·관리주체·검사기관 확인 |
| ISO 13482, ISO 3691-4 | [사실] 공개 초록에서 용도별 범위 확인. 전문 미열람[^ref-1602][^ref-470] | 국내 법정 인증, KS 채택, 제품·페이로드 변경 영향, 전기·무선·배터리 요구는 전문 담당이 확인. CE·ISO 표기만으로 국내 빌딩 사용 승인으로 간주하지 않는다 |

**개인정보 운영 설계 제안:** 주행용 순간 처리, 점검 결과, 사고 조사 영상, 서비스 인계 증거의 목적·저장 위치·보관 기간·접근자를 따로 정한다. 센서 영상을 전부 클라우드에 보존하는 것을 기본값으로 두지 않는다. 저장하지 않는 주행 영상도 법 적용 검토를 면제한다고 단정하지 않는다. 얼굴 인식은 안내·배송의 필수 조건으로 두지 않는다. 시행령·고시의 세부 표시 요건은 원문 확인 뒤 운영 정책을 확정한다.

**적용 제외:** 공도·보도의 실외 운행, 의료 행위·의약품 운송, 폭발 위험 구역은 이 시나리오의 승인 범위가 아니다. 그 서비스로 넓힐 때는 관할 법령·인증·보험·현장 조건을 새로 조사한다.
