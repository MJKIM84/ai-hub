# 로봇 선택과 서비스 설계

<!-- auto:page-status:start -->
> 페이지 상태: published · 신뢰도: medium · 페이지 버전: 1 · 마지막 갱신: 2026-10-12 · 마지막 실행: 없음
<!-- auto:page-status:end -->

4휠 로봇과 4족 로봇을 같은 구성 단위로 비교하고, 순찰·배송·안내 세 서비스에 어느 기종이 맞는지, 이종 로봇을 도입할 조건은 무엇인지, 역할별로 누가 무엇을 할 수 있는지, 서비스마다 요청에서 종결까지 여섯 단계가 어떻게 흐르는지를 정리한다. 제품 관련 문장은 제조사 문서에 근거한 조사 결과이고, 서비스 설계·적합성·권한·계약은 **[의견]**이다. 자료 번호는 [핵심 학습 자료](core-materials.md)의 카드다.

**조사용 가정:** 대한민국 다층 복합 업무빌딩. 로비·사무실·공용 복도·공용 승강기·출입통제 구역에서 사람과 로봇이 공간을 공유한다. 물품은 비위험 일반 소형 물품을 우선 가정하고, 의료품·현금·위험물·냉장품 운송은 제외한다.

## 상용 제품을 같은 구성 단위로 비교하기

[추정] 벤더 주장: RB-SUMMIT은 Robotnik이 판매하는 자율 이동 플랫폼이며 공식 설명상 연구개발 용도다.[^ref-1591] Spot은 Boston Dynamics의 점검 중심 4족 플랫폼이다.[^ref-1595] 어느 쪽도 본체만 사면 방문객 안내·배송함·상하차·시설 권한까지 완성되는 것으로 보지 않는다.

| 비교 항목 | 4휠 RB-SUMMIT | 4족 Spot | PM 확인·선택 기준 [의견] |
|---|---|---|---|
| 운동학 | 2024 데이터시트: 구동 모터 4개, skid steering / mecanum의 두 구성. 공개 ROS 2 시뮬레이션 목록은 skid-steering만 명시[^ref-1592][^ref-1594] | 다리당 3자유도, 총 12자유도[^ref-1596] | 구매할 바퀴·구동·제어기 구성을 먼저 고정한다. 네 바퀴만으로 차동·Ackermann·횡이동 가능 여부를 정하지 않는다 |
| 주행 알고리즘 | ROS 2 기반. 소프트웨어 소개에 여러 주행 모듈이 있지만 특정 구매품에 어느 planner가 들어가는지는 미확인[^ref-1593] | GraphNav의 목적지·경로 명령과 피드백 공개[^ref-1579] | 차체 외형과 특정 알고리즘을 일대일로 연결하지 않는다. 통로에서 실제 궤적·재계획·정지 동작을 확인한다 |

| 문턱·경사·계단 | 2024 표의 최대 경사는 80%(각도가 아님). 하중·타이어·표면 조건이 없어 현장 한계로 쓰지 않는다. 문턱·연속 계단 허용값 미확인[^ref-1592] | 현재 제품 표: 경사 ±30°, 최대 단차 300 mm. Gamma SDK 설명의 계단 조건과 구별[^ref-1595][^ref-1596] | 단일 단차와 연속 계단·참·회전·내려가기·난간·추락 위험을 따로 승인한다. Spot으로 모든 계단을 다닐 수 있다고 제안하지 않는다 |
| 바닥 | skid/mecanum 구성에 따라 횡방향 이동·미끄러짐·접촉 특성 검토 필요 | 발 접촉·보행 안정성·넘어짐과 복귀 공간 검토 필요 | 기름·물기·카펫·줄눈·반사면을 실제 조건으로 시험한다. "4족이라 기름에 강하다"는 공개 비교 근거는 없다 |
| 적재 | 제조사 제시 50 kg. 적재함·브래킷·센서와 화물을 합산[^ref-1591] | 합산 페이로드 최대 14 kg. Arm(8 kg)도 포함[^ref-1595][^ref-1597] | 총질량·무게중심·상부 외곽·전도 위험·센서 가림을 검토한다 |

| 센서·점검 | 현재 표: RGBD·2D LiDAR·IMU 등. 열·음향 점검 장비는 별도 구성[^ref-1591] | 본체 인지 센서와 점검용 열·음향·고해상도 페이로드를 구별[^ref-1595][^ref-1600] | 주행 센서의 영상이 해당 점검의 측정 정확도를 만족하는지 확인한다. "카메라 있음"을 "열화상 점검 가능"으로 바꾸지 않는다 |
| 충전·배터리 | 현재 페이지: 48 V 15 Ah, 최대 5시간, 충전소 포함. 실제 운용 주기·충전 시간 미확인[^ref-1591] | 현재 제품: 평균 90분, 564 Wh, 충전 60분. Gamma 문서는 605 Wh·120분[^ref-1595][^ref-1596] | 운행·측정·통신·대기·충전·예비 잔량을 합산한다. 5시간 대 90분을 곧바로 경제성 우열로 쓰지 않는다 |
| 통신 | 현재 제품에 Wi-Fi·5G 라우터 표기. 국내 주파수·통신사·인증·망 접근 조건 확인 필요[^ref-1591] | Wi-Fi·이더넷. 추가 통신 페이로드는 별도 구성[^ref-1596][^ref-1597] | 승강기 안과 층간 로밍을 포함해 패킷 유실·지연·복귀를 측정한다 |
| 소음·사람 수용성 | 같은 시험 조건의 공개 수치 미확인 | 같은 시험 조건의 공개 수치 미확인 | dBA, 야간 민원, 놀람·거리·이탈률, 휠체어·시각·청각 특성을 포함해 비교한다. 4족이 친근하거나 시끄럽다고 단정하지 않는다[^ref-1606] |
| 개발·관제 | ROS 2·RLC·Command Manager 공개 설명. 실제 계약의 API·권한·취소·피드백·호환 판은 미확인[^ref-1593] | SDK 5.2.0의 명령·상태·로그·GraphNav 공개. Orbit 판 차이 확인 필요[^ref-1598][^ref-1383] | 기능 권한표·API 샘플·시험 기체를 확보한다. 두 제품의 VDA 5050 3.0 기본 지원은 미확인 |
| 유지보수 | 마모품·센서·배터리·구동계·SW 지원의 범위·주기·국내 출동 SLA 미확인 | 발·다리·센서·배터리·페이로드·SW 지원의 범위·주기·국내 출동 SLA 미확인 | 일상 점검, 예방 정비, 고장 교체, 대체 기체, 지도·펌웨어 변경을 계약에서 분리한다 |
| 구매·운영 가격 | 확인한 공식 페이지에 현재 견적 금액 없음 | 확인한 공식 페이지에 현재 견적 금액 없음 | 본체·옵션·연동·교육·설비·구독·보험·운영 인력·철수 비용을 견적 요청한다. 과거 기사 가격을 현재 국내 도입가로 쓰지 않는다 |

표의 "미확인"은 제품에 기능이 없다는 뜻이 아니다. 제품 사양의 판과 상충은 [핵심 학습 자료](core-materials.md)의 S01~S04에 있다.

## 서비스 적합성과 이종 로봇의 도입 조건

[의견] 주행 가능한 경로, 데이터 품질, 사용자 경험, 운영 비용을 평가한 뒤 기종을 고른다.

| 서비스 | 4휠 중심안 | 4족을 검토할 조건 | 한 종류로 충분한 경우 | 이종 운영이 필요한 근거 |
|---|---|---|---|---|
| 순찰·설비 점검 | 평탄한 로비·복도·승강기로 접근 가능한 점검점. 필요한 센서 장착 | 승강기로 우회할 수 없는 계단·비정형 접근 구역에 중요한 점검점이 있고, 해당 구성이 시험을 통과 | 핵심 점검점이 모두 평탄 경로에 있으면 4휠만으로 시작. 이동 점검만 필요하고 4족이 전체 임무를 감당하면 4족만도 비교 | 계단 구역의 점검 가치가 4족의 추가 인수·정비·관제 복잡도보다 크다는 확인 |
| 배송 | 적재함·잠금·사용자 알림을 갖춘 4휠을 우선 후보로 | 계단 운반을 꼭 해야 하고 충격·하중·분실·인계 위험을 별도로 해결할 수 있을 때 | 승강기 연동과 직원 상하차로 모든 구간을 해결하면 4휠만으로 충분 | 4족에 배송을 억지로 배정하지 않는다. 배송은 4휠, 접근 제한 점검만 4족으로 분업 가능 |
| 안내 | 접근 가능한 경로·화면·음성·직원 인계 중심의 완제품이나 구성 비교 | 검증된 운영 목적이 있고 이용자 수용성·접근성에서 추가 가치가 확인될 때 | 직원·키오스크·모바일 지도만으로 해결하면 안내 로봇을 도입하지 않는 선택도 가능 | 외형 다양성 자체는 도입 근거가 아니다. 안내를 위해 4족을 추가할 이유는 현재 근거로 부족 |

**조건부 추천:** 배송·일반 안내·평탄부 점검을 4휠 중심으로 시범 운영하고, 계단·설비 구역의 점검 공백을 사람·고정 센서·시설 개선과 비교한 뒤 4족을 추가한다. 이는 제품 성능이나 ROI가 검증됐다는 결론이 아니라 단계적 투자 제안이다. NAVER 1784는 빌딩·직원 앱 결합의 사례로,[^ref-1599] BMW는 센서 기반 점검의 사례로만 쓴다.[^ref-1600]

## 역할별 요구와 권한

[의견] 최소 권한과 책임 분리의 초기안이다. 실제 법적 책임·보험 보상은 계약과 사고 원인에 따라 따로 판단한다.

| 역할 | 주요 요구 | 허용할 동작 | 기본 제한·감사 |
|---|---|---|---|
| 이용자·방문객 | 쉬운 요청, 예상 대기·도착, 취소, 사람의 도움 | 본인 요청 조회·취소, 허용 목적지 선택, 언어·접근성 옵션 | 다른 이용자의 위치·영상, 관리구역 지도 열람 금지 |
| 발송자·수령자 | 물품 식별·잠금·인계 증명·부재 대응 | 허용 물품 등록·적재 확인, 일회용 수령 인증, 이의 제기 | 수령 인증 재사용·임의 적재함 개방 금지. 이름 대신 최소 식별 토큰 |
| 현장 운영자 | 대기열·예외·상하차·사람 대체 | 물품 인계, 구역 일시 중지, 승인된 매뉴얼에 따른 현장 조치 | 임의 펌웨어·안전 설정 변경 금지. 수동 완료는 사유·증거 필수 |
| 시설 관리자 | 설비 운영·피난·출입·충전 공간 | 시설 사용 시간·권한 승인, 수동 점유·정비 모드 지정 | 시설 인터록 우회 불가. 로봇 플랫폼과 독립된 설비 비상 권한 유지 |
| 관제 담당자 | 작업·로봇·시설의 현재 상태와 오래된 상태 구별 | 재배정, 운영 정지, 검증된 경로 변경, 원격 지원 요청 | 직접 원격 조작은 별도 자격·권한·명령 소유권. 취소 요청을 물리 정지로 표시 금지 |
| 유지보수 담당자 | 재현 조건·로그·부품·버전 | 정비 모드, 진단, 승인된 업데이트·롤백 | 서비스 중 무단 업데이트 금지. 변경과 재승인 이력 보관 |
| 비용을 지불하는 고객사 | 성과·비용·책임·퇴출 가능성 | 서비스 범위·SLA·예산·인수 승인, 집계 보고 조회 | 성과 조회 권한이 원본 영상 무제한 열람 권한은 아니다 |

영상과 권리 처리는 S14·S15, 설비 권한은 S08·S16을 함께 검토한다.

## 순찰 서비스 흐름

[의견] 순찰의 유료 가치는 "로봇이 돌아다님"이 아니라 **정해진 점검을 신뢰할 수 있는 데이터와 조치 기록으로 끝냄**이다. 측정 조건이 중요하다는 근거는 S06·S18이다.

| 단계 | 정상 흐름·행위자 | 예외 처리 | 관리자 화면 | 의뢰자에게 알릴 상태 |
|---|---|---|---|---|
| 요청 | 시설 운영자가 정기 일정이나 설비 알람으로 점검 요청. 점검점·센서·유효기간 지정 | 같은 알람의 중복, 점검 금지 시간 확인 | 점검점, 자산 id, 목적, 우선순위, 마지막 유효 측정 | 접수 대기 / 불가 사유 |
| 접수 | 출입 권한·센서 교정·점검 조건 확인 | 고장 센서·권한 없음은 다른 구성이나 사람으로 전환 | 측정 방법·범위·품질 기준과 구성 버전 | 접수 / 준비 필요 |
| 배정 | 경로·배터리·시설 예약·센서 능력에 맞는 기체 선정 | 도달 불가·충전 경쟁이면 일정 조정 | 후보와 제외 이유, 마감 위험, 배정자 | 예정 시간 / 지연 |
| 수행 | 점검점 도착 → 자세·거리 확인 → 측정 → 품질 검사 | 흔들림·가림·통신·센서 실패는 제한된 재측정 뒤 사람 확인 | 도착 상태와 측정 상태를 별도 열로 | 진행 중 / 일부 확인 필요 |
| 완료 확인 | 필수 점검의 유효 데이터 저장, 검토 결과 연결 | 이상 데이터는 사람 확인 → 보전 티켓 → 조치 → 재측정까지 별도 상태 | 유효 커버리지, 누락, 데이터 위치, 조치 담당·기한 | 점검 완료 / 조치 진행 중 |
| 예외 종결 | 재점검, 사람 대체, 고객 승인 누락 처리 | 누락을 정상 측정으로 채우지 않는다 | 예외 원인, 인력, 추가 비용, 잔여 위험 | 일부 완료 / 실패와 후속 일정 |

점검점 기록 템플릿: 자산 id / 위치·층·지도 판 / 센서·교정 판 / 측정 거리·각도·허용 오차 / 조명·가림 / 측정값·품질 표시 / 증거 위치 / 관찰 시각 / 판정자 / 후속 티켓 / 재점검 기한. 고정 센서는 상시 감시가 필요한 지점, 이동 센서는 접근 가능한 여러 지점을 순회하는 데 비교해 쓴다. 측정 공백과 주기는 고객이 합의한다. 유효 측정과 도착의 구분은 [현장 적용·운영 검증 — 이동 점검과 설비 상태 관리](../field-readiness-rop/mobile-inspection-and-phm.md)에 있다.

## 배송 서비스 흐름

[의견] 초기 범위는 직원 적재·수령자 하역이다. 자기 상하차는 추가 로봇팔이나 설비가 검증되기 전까지 포함하지 않는다.

| 단계 | 정상 흐름·행위자 | 예외 처리 | 관리자 화면 | 발송자·수령자 상태 |
|---|---|---|---|---|
| 요청 | 발송자가 물품 id·규격·무게·출발·도착·수령 기한 입력 | 규격 초과·금지 물품·보안구역이면 거절 또는 사람 배송 | 서비스 가능 구역, 규격 기준, 요청 원본 | 요청됨 / 이용 불가 |
| 접수 | 요청 id로 중복 방지, 권한·수령 가능 시간 확인 | 같은 요청 재전송은 같은 작업 반환 | 접수 시각, 납기, 취소 가능 구간 | 접수됨 / 예상 시간 |
| 배정 | 빈 적재함·경로·배터리·시설 조건에 맞춰 배정. 직원이 스캔·적재·잠금 확인 | 잘못 적재·잠금 센서 이상은 출발 차단 | 화물 보관 책임자, 적재함, 잠금 상태 | 적재 대기 / 배송 준비 |
| 수행 | 이동 → 승강기·출입 세션 → 도착 알림 | 문·승강기 불가, 사람 혼잡, 위치 상실이면 안전 대기·지연·대체 | 로봇·시설 상태의 나이, 작업 단계, 화물 실제 위치 | 이동 중 / 지연·도움 요청 |
| 완료 확인 | 수령자 인증 → 개방 → 물품 인출 확인 → 인계 영수증 | 수령자 부재, 인출 불일치, 분실·손상 주장 시 자동 완료 금지 | 인계 시각·주체·증거·확인 상태 | 수령 대기 / 수령 완료 / 확인 필요 |
| 예외 종결 | 기한 초과 뒤 직원 회수·재배송·반송 승인 | 취소해도 물품은 사라지지 않는다. 누가 회수·보관할지 지정 | 재배정과 물리 인계 기록, 보상 처리 티켓 | 반송 중 / 반송 완료 / 분쟁 처리 |

인계 책임 원장 예시: 발송자 → 적재 담당자 → 운송 운영사 보관 → 수령자의 전환마다 물품 id·개수·포장 상태·잠금과 인출 확인·시각·승인자를 기록한다. ROP가 작업을 다른 로봇에 배정해도 물품이 자동으로 옮겨진 것은 아니다. 약관에는 허용 물품, 포장 의무, 고가품 제한, 분실·파손 통지, 조사·보험·보상 범위를 정한다.

## 안내 서비스 흐름

[의견] 목적지 도착만으로 안내 성공을 세지 않는다. 방문객이 목적지나 인계 직원에게 실제로 연결됐는지 확인한다. 동행의 평가 관점은 S17이다.

| 단계 | 정상 흐름·행위자 | 예외 처리 | 관리자 화면 | 방문객 상태 |
|---|---|---|---|---|
| 요청 | 키오스크·앱·직원이 목적지·언어·접근성 요구 접수 | 음성 이해 실패는 선택형 화면이나 직원으로 전환 | 목적지, 안내 가능 경로, 언어 | 목적지 확인 |
| 접수 | 방문 권한·예약·동행 범위 확인 | 권한 없는 문 뒤로 이동 금지. 방문 확인 담당자 호출 | 권한 토큰·유효기간·허용 구역 | 인증 필요 / 접수됨 |
| 배정 | 보행 속도·혼잡·승강기·접근 가능한 경로 고려 | 로봇이 있어도 접근성 요구를 만족하지 못하면 직원 안내 | 예상 시간, 동행 방식, 도움 필요 | 곧 안내 시작 |
| 수행 | 분명한 출발 신호 → 동행 → 교차로·문 앞 재확인 | 따라오지 않으면 승인된 장소에서 대기·질문·직원 호출. 다른 사람을 일행으로 대체 추적하지 않는다 | 동행 유지 상태, 혼잡, 연락, 직원 위치 | 천천히 이동 / 잠시 대기 / 직원 연결 |
| 완료 확인 | 방문객 확인 또는 담당 직원 인계 | 로봇만 도착하면 미완료 | 사람 인계, 동행 종료, 실패 사유 | 도착 / 담당자 연결 완료 |
| 예외 종결 | 방문객 취소·이탈·긴급 상황이면 지정 지원 절차 | 추적·녹화 확대 대신 최소 데이터로 도움 요청 | 개입 시간, 직원 인계, 불편 신고 | 안내 종료 / 도움 안내 |

화면·음성·큰 글씨·명확한 멈춤 요청·수어와 청각 대안·다국어는 요구 조사 항목이다. 장애 유형을 추정해 민감정보를 저장하는 방식은 기본안에 넣지 않는다. 얼굴 인식을 필수로 만들지 않고 예약 토큰·배지·직원 확인을 대안으로 둔다.
